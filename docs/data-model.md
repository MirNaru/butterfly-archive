# 데이터 구조

이 문서는 관찰·종·사진·소장·기상·수집 자료의 데이터 구조와 입력 규칙을 정리합니다. 현재 DB 스키마는 버전 16이며 아래 버전별 절은 구조 추가 이력입니다. 종 참고자료·관찰 출처·환경 태그·사진·소장·휴지통·외부 수집 대기함과 선택 등록을 구현했습니다. 미구현 항목은 별도로 표시합니다. 원본 값, 정리한 값, 추정값을 구분하며 모르는 값은 0이나 임의 날짜로 바꾸지 않습니다.

## 관계와 소유 범위

- 한 탐사에는 여러 종별 기록이 연결됩니다. 한 탐사에 여러 종·단계·개별 위치를 기록할 수 있습니다.
- 종별 기록은 확인된 경우 종 정보에 연결합니다. 동정 미확정 관찰도 보존합니다.
- 한 종에는 여러 출현 참고 기간, 분포 자료, 목격 사례, 소장 기록이 연결될 수 있습니다.
- 직접 채집한 소장 기록은 개인 관찰과 연결할 수 있습니다. 구매 자료는 개인 탐사를 자동 생성하지 않습니다.
- 사진·태그·기상은 적용 대상과 출처를 명확히 연결합니다. 종의 일반적 생태와 개별 현장 사실을 혼합하지 않습니다.

각 주요 기록에는 내부 식별번호와 생성·수정 시각을 둡니다. 외부 자료에는 출처·원문·검토 상태를 보존합니다. 엑셀 번호나 종명을 영구 식별번호로 사용하지 않습니다.

## 종 정보

2026-11-04 사용자 지정으로 속명·종소명이 다른 제공자 연결 후보도 linked로 보관합니다. 동일 제공자 이름이 여러 도감 종에 겹치면 연결 판정은 계속 거부하며 대기함의 종 직접 지정으로 선택합니다. 원문 학명과 도감 대표 학명은 보존합니다.

네이처링 수동 읽기는 manual_capture=true와 location_status(public/private_location/missing_location)를 보존합니다. 비공개·미입력 상태는 place_raw가 비어 있고 두 좌표가 null이어야 하며 숨겨진 좌표를 읽지 않습니다. 해당 수동 자료는 위치 없이 검수·간접 등록할 수 있습니다. SurveyInput은 종별 기록이 모두 indirect인 비어 있지 않은 탐사에 한해 위치 공란을 허용하며 직접 관찰·빈 탐사는 위치를 요구합니다. 지도 핀·좌표 기반 지역 근거는 생성하지 않습니다. 자동전송의 위치 제외와 iNaturalist 위치 공개 제한은 유지합니다.

종의 대표 scientific_name과 iNaturalist 연결명은 분리합니다. species_references의 inaturalist_names 배열에 name·taxon_id·status(linked/pending)·source·notes를 저장하며 기존 스키마 14를 유지합니다. 기존 클라이언트가 이 배열을 생략하면 보존합니다. 빈 배열을 명시하면 연결 후보를 제거합니다. 연결 사용은 학술적 동종이명 확정을 뜻하지 않으며 사용자 지정 연결도 근거에 표시합니다.

iNaturalist 등록 판정은 대표 학명 정확 일치와 linked 연결명을 함께 조회하고 후보 도감 종이 하나일 때만 사용합니다. 연결명은 수집 원문의 taxon.id가 있으면 번호까지 일치해야 합니다. 여러 도감 종과 충돌하면 자동 연결하지 않습니다. pending은 등록 연결에서 제외하고 기존 사용자 종 직접 지정은 우선합니다. 수집 원문과 이미 등록한 관찰은 자동 재작성하지 않습니다.

## 출현 참고 기간과 분포

기존 출현 참고 기간은 연간 36개 구간으로 보존합니다. 각 월의 1~10일, 11~20일, 21일~월말이며 2월도 포함합니다. 윤년의 2월 마지막 구간은 9일입니다. 한살이 기간은 이 구간과 함께 선택적 일 단위 시작·끝 경계를 지원합니다.

도감 기간의 원문과 출처를 보존하며, 편집 화면은 초순 1~10일, 중순 11~20일, 말순 21~말일, 초중 6~15일, 중후 16~25일을 지원합니다. 일 단위 경계는 윤일을 포함한 2000년 기준 1~366 값인 start_day/end_day로 함께 저장합니다. 두 값이 있으면 그림·단계 추정·출현 계산에서 기존 36구간보다 우선하며, 없으면 기존 구간을 사용합니다. 입력된 단계별 기간의 중첩과 연말·연초 연결을 보존하고, 기존 도감 경계나 실제 관찰 날짜를 자동으로 이동하지 않습니다.

한살이 기간에는 종, 성장 단계(알·애벌레·번데기·어른벌레), 시작·끝 구간과 선택적 일 단위 경계, 출처를 연결합니다. 서로 떨어진 기간은 별도 구간으로 저장하며 시작이 끝보다 뒤면 연말·연초를 연결합니다. 사용자가 제공한 기존 엑셀의 출현 기간은 어른벌레 기준으로 확정했습니다. 네이처링 목격 사례를 주로 취합한 사용자 정리 자료이며 원본 사례별 출처를 검증한 상태는 아닙니다. 알·애벌레·번데기의 출현 기간으로 복사하지 않습니다.

색이 없는 칸은 원본의 출현 표시가 없는 상태이며, 확실한 부재로 간주하지 않습니다. 실제 관찰 날짜는 36구간으로 손실 압축하지 않고 일 단위로 보존합니다.

분포 지역은 종의 참고 분포이며 개인 관찰 좌표가 아닙니다. 지역 원문을 보존하고 정규화한 행정구역은 별도로 연결합니다. 분포가 있다는 이유로 도시 중심점에 관찰 핀을 생성하지 않습니다.

## 참고 목격 사례

종, 확인된 날짜와 날짜 정확도, 장소, 증거·원본 URL, 출처, 검토 상태를 관리합니다. 연도만 확인되면 연도만 저장하고 월·일을 만들어 넣지 않습니다.

미접 태그의 괄호 안 연도는 등록된 확인 자료 중 최신 목격 연도 하나이며 전체의 마지막 목격 연도라고 단정하지 않습니다. 여러 연도·지역의 관찰 사례 자체는 각각 보존합니다. 사용자 제공 설명은 원문이 검증된 외부 사실과 구분합니다. 외부 목격을 개인 관찰이나 국내 정착의 증거로 자동 확정하지 않습니다.

## 소장 정보

종, 성별, 수량 또는 미상, 취득 경로, 선택적 취득 날짜, 연결된 개인 관찰, 사진·메모와 원본 출처를 관리합니다. 취득 경로는 직접 채집, 구매, 기타, 미확인입니다.

기존 엑셀 암수 체크는 소지 여부만 뜻합니다. 체크를 수량 1 또는 직접 채집으로 변환하지 않습니다. 취득 경로는 확인 전까지 미확인입니다. 같은 종의 구매와 직접 채집 자료가 함께 존재할 수 있습니다. 구매 장소·취득 날짜는 야생 관찰 장소·날짜가 아닙니다.

관찰 종 수, 직접 채집 수량, 소장 종 수를 별도 집계합니다. 수량 미상은 알려진 수량 합계와 분리하여 표시합니다.

## 사진, 기상, 태그

사진 원본과 썸네일은 별개로 관리합니다. 원본의 임의 삭제·변환·이름 변경을 하지 않습니다. 촬영 시각은 관찰 시각 입력 후보로 제시하며 사용자가 확정한 관찰 시각과 별도 보존합니다. 여러 사진의 시각이 다르거나 촬영 정보가 없으면 임의로 시간을 선택하지 않습니다.

기상은 현장값과 외부 관측값을 구분합니다. 대상 날짜·시각 또는 집계 기간, 관측소, 출처, 조회 시각, 단위, 누락 상태를 보존합니다. 외부값이 현장값을 덮어쓰지 않습니다. 시각 미상 기록의 일별 요약은 시간별 관측값과 명확히 구분합니다. 관측소 값은 현장의 정확한 날씨라고 단정하지 않습니다.

태그는 현장의 외부 환경 조건과 변화를 보완합니다. 흡밀·산란 같은 행동을 기본 태그에 넣지 않으며 그늘 활동·아침 지면 활동 같은 일반적 습성은 도감의 습성에 출처와 함께 기록합니다. 날짜, 개체 수, 성장 단계 같은 구조화된 항목을 태그로 대체하지 않습니다.

## 엑셀 반입과 원본 추적

기준은 제공된 엑셀의 나비 아카이브 시트입니다. 종 정보, 출현 참고 자료, 소지 표시를 분리합니다. 기주식물 아카이브는 연결 참고 자료이며 중복 후보는 자동 병합하지 않습니다. Abandoned나비목록은 반입 대상에서 제외합니다.

원본 파일 식별 정보, 시트·행·열과 원문을 개인 데이터 영역에서 추적할 수 있도록 설계합니다. 소지 목록과 실제 개인 값은 설계 문서나 Git 저장소에 복사하지 않습니다. 반입 전에 건수·중복·빈 값·색 의미·변환 결과 미리보기를 확인하고 백업 및 승인 후 반영합니다.

기존 가중치 점수와 계산식은 참고 자료로 보존하되 기본 추천·예측에는 사용하지 않습니다. 분포 상수 324와 162, 과거 연도 경계 규칙의 근거는 확인되지 않았습니다.

## 보존과 DB 변경

DB를 삭제하거나 초기화하여 변경 오류를 해결하지 않습니다. 스키마 변경 전 영향, 기존 자료의 이동 방식, 백업과 복구 방법을 제시합니다. 사용자용 DB·사진 백업·복원은 사용자 요청으로 보류했습니다. 스키마 이전 보호 복사본은 유지합니다. 기록 삭제와 사진 파일 삭제는 분리하고 사진 원본은 자동 삭제하지 않습니다.

## 구현된 스키마 버전 2

- surveys: 날짜, 장소명, 좌표와 입력 방식, 목적, 메모, 생성·수정 시각입니다.

- 한 탐사와 그 기록은 같은 트랜잭션으로 저장합니다. 존재하지 않는 종이나 저장 실패 시 부분 저장하지 않습니다.
- 미발견 기록은 대상 종을 요구하고 관찰된 단계·성별·수량·채집·동정 결과를 허용하지 않습니다. 관찰 수량이 알려졌다면 채집 수량이 이를 넘지 않도록 검증합니다.
- 가상환경의 기존 의존성만 사용했습니다. 초기 엑셀 반입은 국명·학명·기주식물부터 진행했으며, 이후 소장 자료는 사용자 확인을 받아 성별·취득 경로·알려진 수량을 반영했습니다.

앱 시작 시 user_version이 0이면 기록·연동 테이블을 생성하며, 1이면 기존 기록을 유지하고 연동 테이블만 추가합니다. 내용이 있는 기존 파일은 먼저 SQLite backup API로 같은 폴더에 `.before-v2-날짜.bak` 백업을 만듭니다. 스키마 추가와 버전 기록은 트랜잭션 안에서 수행하며 실패 시 되돌립니다. 같은 이름의 기존 테이블이나 지원하지 않는 버전이면 실행을 중단하고 기존 자료를 보존합니다. 버전 2에서는 반복 변경하지 않습니다.


- api_usage: 서비스·한국 날짜별 호출 시도 수입니다. 호출 전 트랜잭션으로 예약하며 실패도 누적합니다.
- weather_stations: 조회 대상 시점별 관측소 목록과 수집 시각입니다. 현재 관측소 위치를 과거 기록에 일괄 적용하지 않습니다.
- weather_samples: 관측소 번호·시간/일자료 구분·대상 시점·원본 수치 문자열·해석 값·단위·출처·조회 시각입니다. 새로 조회한 값은 별도 행으로 보존합니다.
- weather_links: 조사 또는 종별 기록 중 하나와 기상자료를 연결합니다. 연결 당시 날짜·시각·장소·좌표, 관측소 정보와 거리를 보존합니다. 기록 조건이 바뀌면 이전 자료임을 표시합니다.
- 시간 미상은 일자료, 시간 지정은 해당 시간 직전 정시의 ASOS 시간자료입니다. 저장값 자동 갱신은 없습니다. 같은 관측소·자료 종류·대상 시점의 저장값을 재사용합니다. 명시적 재조회는 해당 기록만 새 자료와 연결하며 실패 시 기존 연결을 유지합니다.
- 음수 기온은 유효 범위 내에서 보존합니다. 강수량 등의 음수 결측값은 null로 표시하고 원본 문자열도 보존합니다. 시간자료의 강수량은 해당 시각까지의 일 누적량입니다.
- 좌표는 WGS84 위도·경도 필드로 저장합니다. 입력 방식에는 `map`과 `address`를 추가했으며 두 방식 모두 좌표 쌍을 요구합니다.

- species_references: species_id를 기준으로 검증된 JSON 참고자료와 수정 시각을 저장합니다. 기존 species·surveys·observations와 기상 연결은 변경하지 않습니다.

DB 테이블·버전 변경은 없습니다.

- 과거 채집 여부는 미확인·채집한 적 있음·채집한 적 없음과 확인 근거로 관리합니다. 앱에 해당 종의 직접 관찰 채집 기록이 있으면 이를 우선합니다. 간접 관찰자의 채집 기록은 내 이력에 포함하지 않습니다. 관찰 기록 부재나 구매 소장은 미채집 확정·직접 채집으로 변환하지 않습니다.
- 보호종 여부는 미확인·해당·아님과 출처·확인일입니다. 별도의 채집 가능 판단은 사용자 확인값, 대상 지역, 적용 시작·종료일, 근거를 저장합니다. 자동 법적 판단 기능이 아닙니다. 목표 지역과 정확히 일치하고 기간 내일 때만 해당 판단을 사용합니다.
- 참고자료 수정은 expected_updated_at으로 동시 편집 충돌을 거부합니다. 출처가 필요한 값은 근거 없이는 저장하지 않습니다.
- 버전 0·1·2에서 3으로 이전할 때 기존 DB를 .before-v3-날짜.bak로 먼저 백업합니다. 필요한 테이블만 같은 트랜잭션으로 추가하며 실패하면 DB 버전과 테이블 변경을 롤백합니다. 3이면 반복 변경하지 않습니다.

## 구현된 기주식물 저장

사용자 요청으로 현재 개인 DB의 도감 282종을 전수 확인하고 22종에 저장된 기주식물 이름에서 명확히 생략된 ‘나무’만 복원했습니다. 대상은 개암·고로쇠·귤·단풍·매실·머귀·무화과·배·복숭아·사과·산초·살구·아까시·아카시·앵두·자귀·자두·초피·탱자·황벽이며 ‘아카시나무’와 ‘아까시나무’는 사용자 지정에 따라 혼용을 유지합니다. 구분 기호·출처·다른 도감 필드·관찰 자료는 보존합니다. 싸리·진달래·호랑버들 등에는 무리하게 접미사를 붙이지 않습니다. 두 차례 보호 복사본과 전체 종의 전후 목록은 로컬 `data/backups/host-tree-names-20261105-141506`, `data/backups/host-tree-names-20261105-141603`에 보관하며 Git에는 포함하지 않습니다. 향후 입력에 자동 적용하는 정제 규칙은 추가하지 않았습니다. 아래 엑셀 원문 반입 설명은 최초 반입 당시의 기록입니다.

종 참고자료 JSON에 host_plants(원문 문자열, 최대 5000자)와 host_plants_source(출처, 최대 2000자)를 추가합니다. 기주식물 값이 있으면 출처가 필요합니다. 기존 JSON에 두 필드가 없으면 빈 문자열로 응답하며 이 JSON 필드 자체는 테이블 구조를 변경하지 않습니다. 전체 DB의 현재 버전은 문서 마지막 휴지통 절을 따릅니다. 종 목록 응답의 host_plants는 같은 참고자료에서 읽는 값이며 별도 복제 저장하지 않습니다.

나비.xlsx의 나비 아카이브 시트 F열 국명, G열 학명, AR열 기주식물에서 282종을 반입했습니다. 기주식물 문자열은 양끝 공백만 제거하고 구분 기호와 원문 표현을 유지합니다. 기주식물 219종, 미등록 63종이며 원본 셀 출처를 함께 저장합니다. 다른 시트·소지 표시·관찰·출현·분포는 이번 반입 대상이 아닙니다.

## 구현된 분류와 기본 표시 순서

종 참고자료 JSON에 family, subfamily, display_order(1 이상 정수 또는 미지정), taxonomy_source를 저장합니다. 분류나 표시 순서가 있으면 출처가 필요합니다. 이 JSON 필드 자체는 테이블 구조를 변경하지 않습니다. 전체 DB의 현재 버전은 문서 마지막 휴지통 절을 따릅니다. 저장되지 않은 분류 필드는 빈 문자열 또는 미지정으로 응답합니다. 편집 화면은 분류·출처를 읽기 전용으로 표시하고 다른 참고자료를 저장할 때 함께 보존합니다.

표시 순서는 사용자 지정 과 순서(호랑나비과, 네발나비과, 흰나비과, 팔랑나비과, 부전나비과), 각 과에서 엑셀 아과 첫 등장 순서, 해당 아과 안의 원본 행 순서로 계산한 순번입니다. 원본 행 위치는 출처에 남기며 원본 엑셀을 수정하지 않습니다. 검은눈그물나비와 푸른줄까마귀왕나비는 각각 뱀눈나비아과와 왕나비아과 끝으로 이동합니다. 아과 소속 확인 자료는 아래와 같으며 아과 내 정확한 계통 분기 순서를 주장하지 않습니다.

- [검은눈그물나비 국내 보고 논문](https://db.koreascholar.com/Article/Detail/436468)
- [푸른줄까마귀왕나비 국내 보고 논문](https://db.koreascholar.com/article/Detail/414540)

282종에 분류와 표시 순서를 추가했으며 나머지 JSON 값, 종 식별번호, 이름, 기주식물, 탐사·관찰·기상 자료는 전후 대조로 보존을 확인했습니다. 표시 순서가 없는 종은 분류 목록 뒤에 내부 식별번호 순서로 표시합니다. 사용자 지정 관찰 표의 날짜·국명·수량 정렬과 탐사 결과의 남은 일수 정렬은 별도 기능입니다.


## 구현된 관찰 출처 · 버전 4

observations에 source_type(TEXT, direct 또는 indirect, 기본 direct)와 source_note(TEXT, 기본 빈 문자열)를 추가합니다. API는 source_note를 최대 2000자로 검증하며 indirect이면 공백이 아닌 근거가 필요합니다. 원문 주소 또는 자료명·관찰자를 원문으로 보관합니다. 수동 입력 외에 네이처링 확장 수집과 사용자 선택에 따른 간접 관찰 등록을 지원하며 직접 관찰로 바꾸지 않습니다. 같은 탐사 안에서도 종별 기록마다 출처를 구분할 수 있습니다. 탐사 등록·수정과 재조회에서 필드를 유지합니다.

기존 버전 0·1·2·3을 4로 이전할 수 있습니다. 기존 자료가 있는 DB는 변경 전 .before-v4-날짜.bak로 백업하고 같은 트랜잭션에서 필요한 이전과 열 추가를 수행합니다. 실패하면 추가 열과 버전 변경을 되돌립니다. 기존 ID·종·참고 JSON·관찰·기상 연결을 보존하며 기존 관찰은 direct와 빈 source_note로 유지합니다. 버전 4의 관찰 출처 열은 중복 추가하지 않으며 현재 코드는 필요한 후속 버전 이전도 함께 수행합니다.

종 참고 행은 화면의 조회 결과일 뿐 observations에 저장하지 않습니다. 날짜·기상·좌표를 갖는 가상 관찰을 만들지 않습니다. 종 참고 후보를 계산할 때 검색 후 기록이 아니라 전체 원본 관찰의 종 ID를 사용하여 필터에서 제외된 기록을 참고 행으로 대체하지 않습니다. 실제 관찰과 출현 기준일·참고 분포를 구분합니다.


## 한살이 기간과 생태 참고자료

기존 species_references.payload_json을 확장하며 관찰 데이터는 유지합니다. 이 절의 JSON 확장은 DB 스키마를 추가 변경하지 않으며 현재 전체 버전은 모바일 사진 대기함 절의 버전 14를 따릅니다. 빠진 새 필드는 읽을 때 빈 기본값을 적용합니다.

- lifecycle: id, stage(egg/larva/pupa/adult), start/end(1~36), 선택적 start_day/end_day(1~366), source(필수), edition, region, notes, enabled를 갖는 도감별 구간입니다. 일 단위 경계는 시작과 끝을 함께 입력하며 두 값이 있으면 우선합니다. 적용하는 경계의 시작이 끝보다 뒤면 연말·연초 연결입니다. 최대 100구간이며 ID 중복을 거부합니다.
- habitat, habits, other_notes: 각각 최대 5000자입니다. 하나라도 입력하면 ecology_source가 필요합니다.
- _lifecycle_history: 서버가 이전·현재 한살이 저장본의 변경 시각, lifecycle, 기존 어른벌레 periods와 source를 보존합니다. 사용자 입력으로 덮어쓸 수 없습니다. 전체 생태 메모 이력이나 자동 백업 기능은 아닙니다.
- GET /api/species/catalog는 분류 순서의 종과 현재 참고자료를 함께 반환합니다. 개별 reference 조회는 lifecycle_history도 반환하고 저장은 expected_updated_at으로 충돌을 거부합니다.

사용 중인 새 어른벌레 구간이 있으면 탐사 기간 계산에 우선 사용합니다. 없으면 기존 periods를 어른벌레에만 적용합니다. 알·애벌레·번데기로 복사하지 않습니다. 오래된 판본은 enabled를 끄고 보존할 수 있습니다.

그림은 사용자 확인 동정·단계 지정·실제 관찰만 집계하며 개체 수로 가중하지 않습니다. 직접 관찰은 같은 탐사·종·단계·날짜·장소·좌표를 한 사례로 묶고 간접 관찰은 조사 대신 출처 문자열까지 같을 때 묶습니다. 원본 ID는 모두 남습니다. 출처 표기가 다른 중복을 자동 판별하지 않습니다.

윤일을 포함한 366일 축에 연도·장소 문자열·직접/간접 조건을 적용하며 기본은 전체입니다. 관찰 통계는 도감 참고 구간과 독립적으로 계산합니다. 같은 단계의 관찰 사례 전체를 사용하고 20사례부터 연간 분포 상자를 표시하며 미만이면 점만 표시합니다. 도감 밖 사례와 도감이 없는 종도 동일하게 포함합니다. 가장 긴 연간 관찰 공백을 경계로 날짜 축을 나누며 겨울 관찰은 연초 날짜에 366을 더해 연말과 잇습니다. 공백 길이가 같으면 기존 연초·연말 경계를 우선합니다. 여러 발생 차수의 자동 분리는 하지 않으며 연간 분포 상자가 빈 기간의 연속 출현을 의미하지는 않습니다.

사분위수는 선형 보간 Type 7 방식, 수염은 1.5 IQR 한계 안의 최솟값·최댓값이며 수염 밖은 별도 점입니다. 연말 구간은 연초 날짜를 다음 해 축으로 이어 계산하고 양끝으로 나눠 그립니다. [NIST 설명](https://www.itl.nist.gov/div898/handbook/eda/section3/boxplot.htm), [R 사분위수 정의](https://stat.ethz.ch/R-manual/R-devel/library/stats/html/quantile.html)를 참고합니다. 관찰 편향을 보정한 출현 예측은 아닙니다.

## 환경 태그 · 버전 5

- tags(id, name): 이름 1~60자, 앞뒤 공백 제거, 같은 이름의 중복 생성 방지. 내부 공백·대소문자·동의어를 자동 정규화하지 않습니다.
- survey_tags(survey_id, tag_id), observation_tags(observation_id, tag_id): 복합 기본키와 외래키를 갖습니다. 기존 탐사·관찰 테이블의 열 값은 수정하지 않습니다.
- 기본 목록: 강풍, 안개, 지면 젖음, 태풍, 관찰 전 강우, 관찰 후 강우, 하천 범람, 벌초, 예초, 농약 살포, 공사, 벌목, 탐방객 많음, 차량 통행 많음입니다. 전후 강우의 실제 시점·정도는 메모에 남기며 기상청 자료로 자동 확정하지 않습니다.
- GET /api/tags: 기본·사용자 목록을 명시적 연결 수 내림차순, 동률은 등록 순서로 반환합니다. POST /api/tags: 새 이름을 로컬 DB에 기억합니다. 같은 이름이면 기존 항목을 반환합니다. 직접 추가는 기록 저장과 별개이며 기록을 취소해도 목록에 남습니다.
- 탐사와 종별 입력·응답의 tags는 이름 목록, 각각 최대 60개이며 정확히 같은 이름은 중복 제거합니다. 탐사 공통 태그가 해당 조사의 모든 종별 기록에 적용되고 개별 태그는 추가 조건입니다. 응답 effective_tags는 둘의 합집합이며 중복 저장하지 않습니다.
- 수정에서 tags를 명시적으로 빈 목록으로 보내면 해당 범위의 선택을 해제합니다. 필드를 생략한 이전 클라이언트는 기존 연결을 보존합니다. 연결 변경과 기록 저장은 하나의 트랜잭션이며 실패·충돌 시 모두 보존합니다. 태그 선택 해제는 목록에서 이름을 삭제하지 않습니다.
- 미선택은 해당 조건이 없었다는 판정이 아닙니다. 관찰·미발견·직접·간접 기록 모두 조건을 지정할 수 있습니다. 도감의 일반 습성과 실제 현장 조건을 혼합하지 않습니다.
- 태그 필터는 선택 항목 중 하나 이상(OR), 다른 필터와는 AND입니다. 공통·개별 합집합을 검색하고 기록 없는 탐사에는 공통 태그를 적용합니다. 기록 없는 종 참고 행은 태그 조건을 확인할 수 없어 제외합니다. 같은 검색 결과가 표와 지도 핀 입력에 전달됩니다.

이전 버전 0~4는 시작 시 5로 이전합니다. 기존 파일을 같은 폴더의 .before-v5-시각.bak에 먼저 보존한 뒤 새 테이블과 기본 태그를 한 트랜잭션으로 추가합니다. 실패하면 버전과 새 테이블을 되돌립니다. 기존 데이터는 삭제·초기화하지 않으며 버전 5 재실행은 중복 적용하지 않습니다. 복구는 서버를 종료하고 현재 파일을 보존한 뒤 백업 복사본을 별도 DB 경로로 열어 확인합니다. 현재 코드는 이전 DB를 현재 버전으로 이전하므로 이전 코드를 함께 사용할 때는 호환되는 백업을 선택해야 합니다. 사용자용 백업·복원 화면은 아직 없습니다.

## 도감 동정 포인트

동정 포인트는 같은 항목 안에서 종 구별과 암수 구분 소항목으로 나눕니다. 종 구별에는 유사종과 구별되는 특징을 개조식으로 적고, 암수 구분에는 수컷·암컷의 특징을 각각 개조식으로 적습니다. 계절형·성장 단계·날개 면 등 구분에 필요한 조건도 유지합니다. 제공된 구분 근거가 없으면 임의로 만들어 채우지 않습니다.

도감의 동정 포인트·습성·기타는 항상 개조식으로 작성합니다. 사용자가 완결된 문장형으로 제공해도 의미별로 나누어 각 줄을 `- `로 시작하는 짧은 항목으로 정리합니다. 원문의 의미·수치·시기·성별·지역·조건·예외·불확실성을 유지하고 없는 사실을 추가하지 않습니다. 출처와 제공된 원문은 정리한 표시 내용과 구분해 보존하며, 해석이 모호하거나 기존 정보와 충돌하면 사용자에게 확인합니다. 이는 앞으로 입력·정리할 내용의 작성 규칙이며 기존 개인 메모를 일괄 변환하는 승인은 아닙니다.

species_references의 기존 JSON에 identification_points(최대 5000자), identification_source(최대 2000자)를 추가합니다. 읽을 때 빠진 값은 빈 문자열로 반환하며 DB 테이블·버전 5·기존 원문은 변경하지 않습니다. 동정 포인트를 입력하면 도감·판본·쪽수 또는 직접 관찰 근거 등 출처를 함께 입력해야 합니다. 자동 동정 확정이나 생물학적 내용을 자동 생성하는 기능은 아닙니다.

도감의 첫 열은 국명 아래 학명을 표시합니다. 기주식물 원문은 그대로 저장하고 화면에서만 괄호 밖 쉼표·세미콜론·줄바꿈을 기준으로 한 항목씩 표시합니다. 괄호 안 쉼표는 분리하지 않으며 식물명 정제·동의어 통합을 수행하지 않습니다. 동정 포인트는 기타 다음인 가장 오른쪽 열에 줄바꿈을 유지하여 표시하고 기존 국명 버튼의 중앙 편집창에서 출처와 함께 수정합니다.

## 엑셀 서식지 반입

원본 나비 아카이브 AS8 머리글을 확인하고 AS10:AS291을 국명·학명과 대조했습니다. 282종 중 내용이 있는 213종의 habitat만 추가하고 69종 빈칸은 미등록으로 유지했습니다. ecology_source에는 서식지에 해당하는 파일명·시트·셀 출처를 추가하며 기존 출처가 있으면 보존합니다. 원문 문자열은 DB에 그대로 보관합니다. API는 기존 검증 규칙에 따라 앞뒤 공백만 정리해 표시하며 AS25의 끝 공백 한 개도 원본 DB 값에는 남아 있습니다. 기존 서식지와 충돌하면 자동 덮어쓰지 않습니다.

실제 반입은 SQLite 전체 백업 후 한 트랜잭션으로 수행했습니다. 서식지·출처·해당 수정 시각 외 모든 참고 JSON 값과 나머지 10개 테이블이 보존되었고, 저장 후 282행의 원문·API 표시·외래키·무결성을 대조했습니다. 다시 실행하면 변경이 없으며 사용자 입력 충돌도 시험용 복사본에서 보존을 확인했습니다. 복구용 before-habitat 백업과 반입 목록은 로컬에만 보관합니다. 이 작업은 서식지 문구 반입이며 생물학적 사실의 외부 검증이나 분포·관찰 위치 생성이 아닙니다.


## 구현된 도감 상태 태그

## 구현된 사진 자료와 기록 연결 · 버전 6

photos는 id, sha256(내용 식별·중복 방지), metadata_json, original_path, thumbnail_path, created_at을 저장합니다. 이미지 자체는 DB에 넣지 않습니다. metadata_json은 파일명·바이트 크기·실제 형식·가로세로 크기·회전 정보·기기명·원문 촬영 시각·원문 시간대·한국 시각 입력 후보·GPS 후보·좌표계 원문·경고를 보존합니다. 파일 생성·수정 시각이나 파일명 날짜는 촬영 시각으로 추정하지 않습니다. 사용자 확인 후 적용한 관찰 값과 사진의 추출값을 구분합니다.

photo_links는 photo_id와 survey_id 또는 observation_id 중 하나를 연결합니다. 같은 사진은 여러 기록에 연결할 수 있지만 같은 대상에는 중복 연결하지 않습니다. photo_ids는 탐사·종별 요청과 응답에 추가되며 양의 정수·중복 제거·최대 2000개입니다. 탐사 저장 트랜잭션에 사진 연결도 포함합니다. 없는 사진 ID는 저장 전체를 거부합니다. 기존 클라이언트의 수정 요청이 photo_ids를 생략하면 연결을 보존하고, 명시적인 빈 목록이면 연결만 해제합니다. 사진·개체·관찰 건수를 동일시하지 않습니다.

촬영 정보 검사는 로컬 백엔드에서 한 번에 최대 32MiB의 파일을 읽습니다. 검사 결과의 변조를 막는 확인표는 24시간 유효하고 서버 재시작 시 무효화됩니다. 정보만 등록하면 확인표를 보내며 사진 파일을 보관하지 않습니다. 원본 보관을 선택하면 해당 파일을 재검사하고 내용 그대로 복사합니다. 원본 파일명은 DB에 보존하고, 보관 복사본 경로는 내용 식별값으로 만들어 경로 조작·이름 충돌을 피합니다. 보관 경로는 응답에 노출하지 않습니다. 이미지 조회는 DB에 등록된 ID의 원본·미리보기만 허용합니다.

기본 폴더는 data/photo이며 시험 DB는 그 DB의 상위 폴더 아래 photo를 사용합니다. BUTTERFLY_PHOTO_DIR로 검증용 폴더를 지정할 수 있습니다. 원본 보관 실패 시 DB를 되돌리고 이번에 생성한 미완성 복사본만 정리합니다. 기존 사진이나 사용자 원본은 자동 삭제하지 않습니다. 새 사진 자료 등록과 탐사 저장은 별도 단계이므로 입력 취소 후에도 등록한 자료는 보관 목록에서 다시 연결할 수 있습니다.

미리보기는 긴 변 최대 640px JPEG이며 회전 방향을 반영하고 EXIF를 제거합니다. 사용자 원본은 바꾸지 않습니다. PNG 투명 영역은 흰색 바탕으로 미리보기를 만듭니다. 사진 목록은 현재 페이지의 최대 12개만 조회·표시하고 서버 조회 상한은 24개입니다. 브라우저 처리는 순차 실행하고 서버의 파일 읽기·검사는 동시에 최대 2개입니다.

버전 5에서 6으로 이동할 때 기존 DB의 before-v6 백업을 만든 뒤 photos·photo_links와 조회 인덱스만 추가합니다. 기존 11개 테이블을 재작성하거나 초기화하지 않습니다. 이전 버전에도 단계별 변경을 적용하며 오류가 나면 버전과 테이블 추가를 함께 롤백합니다. 같은 버전이면 반복 변경하지 않습니다. 실제 사용자 사진 반입이나 관찰 생성은 스키마 이전에 포함하지 않습니다.


## 구현된 소장·취득 경로 · 버전 8

holdings는 id, species_id, sex, possession(owned / not_owned / unknown), quantity(양의 정수 또는 null), acquisition(own_capture / purchase / other / unknown), acquired_date(선택), observation_id(선택), source_note, notes, created_at, updated_at을 저장합니다. holding_photos는 소장 ID와 기존 사진 ID를 중복 없이 연결합니다. 사진 원본과 메타데이터를 복제하지 않습니다. 소장 기록의 삭제·휴지통은 구현하지 않았으며 소지하지 않음으로 현재 상태를 구분할 수 있습니다.

소장 화면은 같은 종·같은 취득 경로의 기록을 한 행으로 묶어 표시합니다. 원래 기록의 ID·성별 수량·출처·날짜·사진 연결은 병합하거나 삭제하지 않습니다. 여러 원본이 있는 행의 국명을 누르면 성별·취득 내역과 수량을 확인하고 수정할 원본을 선택합니다. 성별 필터는 묶음에 해당 성별이 있는지 판단하며 묶음의 다른 성별 수량을 숨기거나 총수량에서 빼지 않습니다.

성별 입력은 수컷·암컷 중복 선택이며 둘 다 선택하면 sex=mixed로 저장하고 수컷 / 암컷으로 표시합니다. mixed는 총 quantity가 필수이며 2 이상이어야 합니다. male_quantity와 female_quantity는 선택 세부 수량으로, 둘 다 비우거나 둘 다 양의 정수로 입력하고 합계가 quantity와 같아야 합니다. 한 성별만 선택한 기록에는 세부 필드를 사용하지 않으며 해당 quantity가 그 성별 수량입니다. 총수량에 마우스를 올리거나 키보드 초점을 맞추면 수컷 n개체 / 암컷 m개체를 표시합니다. 수량 미상은 미상으로 남기며 알려진 일부 합계를 완전한 총수량으로 표시하지 않습니다.

현재 소지함인 기록에만 수량을 입력할 수 있습니다. 미소지와 미확인 상태를 현재 수량 0으로 바꾸지 않습니다. 여러 취득 건의 같은 종은 소장 종 수에서 한 번만 집계하고, 알려진 수량과 수량 미상 건수를 분리합니다. 직접 채집·구매·기타·미확인이 같은 종 안에서 공존할 수 있습니다. 구매는 관찰이나 내 채집 이력으로 변환하지 않습니다. 직접 채집은 실제 관찰 생성 없이 종의 과거 채집 이력 판단에만 추가 반영합니다.

직접 채집은 같은 종의 직접 관찰·채집함 기록을 연결하거나 source_note에 본인 확인 등의 근거가 필요합니다. 연결된 현재 소장 기록의 알려진 수량 합계는 관찰의 알려진 채집 수량을 넘을 수 없습니다. 소장 수정과 관찰 수정 양쪽에서 조건을 검증하고 위반 시 전체 트랜잭션을 되돌립니다. 다른 종·간접 관찰·미발견·미채집 기록은 채집 근거로 연결할 수 없습니다. 취득 날짜는 관찰 날짜를 대신하지 않으며 소장 사진의 EXIF는 자동 적용하지 않습니다.

API는 GET/POST /api/holdings, GET/PUT /api/holdings/{id}입니다. 수정 요청은 expected_updated_at으로 동시 편집 충돌을 확인합니다. 사진 연결을 생략한 수정은 이전 연결을 보존하며 명시적인 빈 목록으로 해제할 수 있습니다. 연결 해제가 사진 자료 자체를 삭제하지는 않습니다.

버전 6에서 7로 이동할 때 holdings·holding_photos와 관찰 연결 인덱스를 추가합니다. 버전 7에서 8로 이동할 때 기존 DB 보호 복사본을 만든 뒤 holdings에 nullable male_quantity·female_quantity 열만 추가합니다. 기존 행·수량·원본 연결과 사진 파일은 재작성하지 않습니다. 오류 시 열·버전 변경을 트랜잭션으로 되돌리고 같은 버전 재실행은 중복 반영하지 않습니다. 기존 엑셀 소지 체크는 성별 원본 행으로 반입했으며 취득 경로와 알려진 수량은 사용자 확인을 근거로 반영했습니다. 사용자용 백업·복원은 사용자 요청으로 작업 범위에서 제외했습니다.

## 탐사·관찰 휴지통 · 스키마 버전 9

record_trash는 id, kind(survey / observation), survey_id, observation_id, deleted_at, restored_at을 저장합니다. 탐사·관찰·기상·사진·태그 행과 원본 파일은 이동하거나 삭제하지 않습니다. 복구되지 않은 탐사 삭제 표지는 자식 관찰도 숨기고, 개별 관찰 삭제 표지는 해당 관찰만 숨깁니다. 복구 표지는 restored_at으로 남깁니다. 활성 삭제 표지에는 종류별 고유 인덱스를 두어 중복 삭제를 막습니다.

일반 탐사 조회·수정, 검색·지도·표·한살이 관찰 입력과 기록별 기상 목록은 활성 기록만 사용합니다. 내 채집 이력의 관찰 근거에서도 삭제된 기록은 제외하되 소장 근거는 별도로 유지합니다. 소장 관찰 연결이 있으면 탐사 전체·개별 관찰 삭제를 409로 거부합니다. 휴지통 관찰에 새 소장 연결을 만드는 것도 거부합니다.

DELETE /api/surveys/{id}, DELETE /api/surveys/{id}/observations/{observation_id}는 expected_updated_at을 받아 삭제 확인 당시 조사 버전과 비교합니다. 소속이 다른 관찰은 거부합니다. GET /api/trash는 현재 휴지통을 읽으며 POST /api/trash/{id}/restore는 expected_deleted_at으로 중복·낡은 복구 요청을 거부합니다. 삭제·복구 시 조사 updated_at을 바꾸므로 열려 있던 이전 수정창은 충돌로 거부합니다.

탐사 복구는 독립적으로 삭제한 자식 관찰을 복구하지 않습니다. 자식 복구는 부모 탐사 복구 후에 가능합니다. 모든 쓰기는 BEGIN IMMEDIATE 트랜잭션으로 수행하고 오류 시 되돌립니다. 휴지통 항목별 완전 삭제는 아래 규칙을 따릅니다. 사용자용 백업·복원 화면은 제공하지 않습니다.

버전 8에서 9로 이동할 때 SQLite 보호 복사본을 만든 뒤 record_trash와 두 인덱스만 추가합니다. 기존 테이블·행·사진은 재작성하지 않으며 실패 시 새 구조와 버전 변경을 함께 되돌립니다. 같은 버전 재실행은 중복 변경하지 않습니다.

## 외부 자료 수집 대기함 · 스키마 10

- collected_observations: source와 source_id 고유 조합, 원문 항목 JSON, 검토 대기 상태, 최초·최근 수신 시각, 클라이언트 수집 시각을 저장합니다. 날짜·장소·기상 원문과 공개 좌표를 보존하며 좌표 정확도는 미상입니다.
- collection_revisions: 내용 변경 시 이전 JSON과 교체 시각을 보존합니다. 동일 내용 재전송은 변경 이력을 추가하지 않습니다.
- collection_connection: 확장 연결 키의 SHA-256 해시만 저장합니다. 키 재발급 시 이전 키를 무효화합니다. 앱 화면에서 발급하고 확장 프로그램에 직접 입력합니다.
- 기존 테이블을 수정하지 않고 세 테이블을 추가합니다. 이전 전에 기존 DB 복사본을 남기며 데이터 비교와 무결성을 검증합니다. 복구 시 서버를 중지하고 이전 복사본을 복원해야 하며 이후 수집 자료는 별도 보존해야 합니다.
- 수집 자료는 대기함에 보존하고, 선택 등록 시 간접 관찰로 연결합니다. 등록 조건은 아래 스키마 11 사양을 따릅니다.

## 외부 자료 선택 등록 · 스키마 11

- collection_imports: 수집 item_id와 등록 observation_id의 고유 연결, 등록 시각, 등록 당시 원문 JSON과 단계 추정 JSON을 저장합니다. 동일 수집 자료는 다시 등록하지 않습니다. 등록 후 원문이나 도감이 바뀌어도 기존 관찰을 자동 갱신하지 않습니다. 휴지통에 넣은 등록 기록도 재등록 대신 복구합니다. 완전 삭제하면 등록 연결은 제거하고 수집 원문은 discarded 상태로 보존합니다.
- 모든 종은 선택 등록을 사용자 검수 완료로 처리하고 identification을 user_confirmed로 저장합니다. 대기 자료는 지도·기록·통계에 포함하지 않습니다. 국명 첫 줄을 도감 국명과 연결하며 필수 날짜·종·공개 위치 검증을 유지합니다.
- POST /api/collection/register는 선택 ID를 받아 한 트랜잭션에서 간접 관찰과 연결 정보를 저장합니다. 각 원문당 하나의 탐사와 관찰을 생성하며 날짜·시각·장소·좌표·출처를 보존합니다. 개체 수·성별·채집 여부는 추측하지 않습니다. 모든 종에 사용자 확인과 체크 검수 근거를 남깁니다. 탐사 목적은 온라인 자료 조사입니다.
- 성장 단계는 관찰 날짜와 등록 당시 도감 lifecycle을 비교해 추정합니다. 일 단위 start_day/end_day가 있으면 우선하고 없으면 기존 36구간을 사용합니다. 비활성 기간과 장소에 맞지 않는 지역 기간은 제외합니다. 겹치면 알 → 애벌레 → 번데기 → 어른벌레 순으로 뒤 단계를 택합니다. 연말·연초를 잇는 기간도 처리합니다. lifecycle이 비어 있으면 기존 어른벌레 periods를 참고하고, 맞는 기간이 없으면 unknown입니다. 날짜를 기간 안으로 옮기지 않습니다.
- 추정 JSON에 적용 방식·관찰 구간·일치한 기간·도감 스냅샷을 남깁니다. 기록 메모에 추정 단계와 원문 기상을 남깁니다. 이 기상 문구를 기상청 관측값으로 변환하거나 추가 조회하지 않습니다.
- 관찰 조회의 source_weather는 등록 당시 원문 스냅샷의 기상 문구·출처명·원문 URL·조건 변경 여부(stale)를 읽기 전용으로 제공합니다. 이미 등록한 자료에도 적용합니다. 날짜·시각·장소·좌표가 바뀌면 이전 조건 자료로 표시하며 원문 값을 덮어쓰지 않습니다. 표와 기상 필터에서 사용하고 기상청 연결 자료가 있으면 표에는 기상청 자료를 우선 표시합니다. 상세에는 가져온 기상도 계속 보입니다.
- 수집 목록 조회는 collection_imports 연결이 존재하는 항목을 제외합니다. 등록 직후와 과거에 등록한 자료 모두 목록에서 빠지며 재수집·수집 삭제 취소·관찰 휴지통 이동으로 다시 나타나지 않습니다. 완전 삭제 후에도 수집 자료는 discarded 상태로 대기 목록에서 제외합니다. 관찰 삭제·복구는 기존 휴지통을 사용하며 수집 원문과 등록 연결은 유지합니다. 이번 변경은 기존 스냅샷을 읽고 목록 조건을 바꾸므로 DB 이전이나 원문 재작성 없이 적용합니다.
- 성장 단계를 수동 수정하면 inference_json의 manual_stage_override와 manual_stage_history에 시각·변경 전후 단계를 남기고 최초 도감 추정 근거를 보존합니다. 조회의 stage_inferred는 수동 수정 후 false가 되며 collection_accepted는 등록된 외부 자료임을 나타냅니다. 사용자가 직접 수정한 성장 단계로 계속 집계하며 원본 수집 날짜·기상과 등록 연결은 유지합니다. 기존 관찰 수정 API의 충돌 검사와 트랜잭션을 사용합니다.
- 버전 10에서 11로 이전할 때 DB 보호 사본을 만들고 연결 테이블 하나만 추가합니다. 기존 행을 변경하지 않습니다. 실패 시 트랜잭션을 되돌리며 복구는 서버 중지 후 이전 사본으로 가능합니다. 사본 생성 후 새로 수집한 자료가 있다면 복원 전에 별도 보존해야 합니다.

수집 자료의 선택 삭제는 POST /api/collection/discard로 review_status를 discarded로 바꿔 목록에서 숨깁니다. 원문·변경 이력·등록 연결·관찰 기록은 보존합니다. 재전송해도 이 삭제 표시는 유지합니다. POST /api/collection/restore는 선택 ID의 상태를 pending으로 돌려 복원하며, 복원 API는 남아 있지만 화면의 삭제 취소 버튼은 제거했습니다. 원문은 DB에 남습니다. 이번 변경은 기존 상태 열을 사용하므로 DB 스키마를 변경하지 않습니다.

한살이 기간은 기존 start/end 36구간과 선택적 start_day/end_day 일 단위 경계를 함께 보존합니다. 일 단위 경계는 윤일 포함 2000년의 1~366 값이며 두 값이 있으면 그림·단계 추정·출현 계산에서 우선합니다. 초순 1~10일, 중순 11~20일, 말순 21~말일, 초중 6~15일, 중후 16~25일을 편집할 수 있습니다. 기존 자료는 그대로 호환됩니다. 단계별 실제 관찰 사례를 중복 제거한 뒤 도감과 독립적으로 20사례부터 연간 분포 상자를 표시하며 소수 사례와 통계적 이상값은 점으로 남깁니다. 도감 추정 단계는 stage_inferred와 사례별 표시로 구분하고 검수 후 등록한 도감 추정 사례도 집계합니다. 원문 날짜를 도감 경계로 이동하지 않습니다.

## 휴지통 완전 삭제

DELETE /api/trash/{trash_id}는 expected_deleted_at으로 활성 휴지통 상태를 확인합니다. BEGIN IMMEDIATE 안에서 소장 연결을 검사하고 별도 읽기 연결의 SQLite backup API로 같은 폴더에 .before-purge-시각.bak 보호 복사본을 만든 뒤 무결성을 검사합니다. 복사 실패는 503, 상태 충돌과 소장 연결은 409로 거부합니다. 삭제 중 오류는 전체 트랜잭션을 되돌립니다. 이 기능 자체는 새 스키마를 추가하지 않습니다. 현재 전체 버전은 14입니다.

탐사 완전 삭제는 모든 자식 관찰과 해당 기록의 휴지통 이력·태그 연결·사진 연결·기상 연결을 제거합니다. 개별 관찰 완전 삭제는 해당 관찰의 연결만 제거하며 부모 탐사와 다른 관찰은 유지하고 부모 수정 시각을 갱신합니다. 사진 파일·photos·tags·weather_samples·소장 자료는 삭제하지 않습니다. 외부 수집 관찰의 collection_imports 연결은 제거하고 collected_observations는 discarded로 바꿉니다. 수집 원문과 collection_revisions는 보존하며 재전송으로 대기함에 자동 복귀하지 않습니다.

앱 내 복구는 제공하지 않습니다. 수동 복구 시 서버를 중지하고 현재 DB를 먼저 보존한 뒤 보호 복사본을 별도 경로에서 확인합니다. 보호 복사본은 삭제 직전 DB 전체이므로 이후 저장한 변경은 포함하지 않습니다. 사용자용 백업·복원 기능과 별개이며 Git에 포함하지 않습니다.

## iNaturalist 공식 API 수집과 진행 위치

공개 좌표의 최대 수평 오차가 50,000m 이하이거나 미상인 자료를 수집합니다. `public_positional_accuracy`는 흐림 처리의 오차를 포함하므로 우선 사용하고, 흐림 없는 자료에서만 이 값이 없을 때 원래 `positional_accuracy`를 사용합니다. 정확도 누락은 null과 accuracy_basis=unknown으로 보존하며 수집합니다. 비공개·좌표 오류·잘못된 오차 값·음수·상한 초과는 새 수집에서 제외하며 이미 저장한 자료는 삭제하지 않습니다. 수집 JSON에 `location_accuracy`·`location_obscured`·`accuracy_basis`와 제공자 원문을 보존합니다. 흐림 위치의 등록은 기존 `location_method=approximate`를 사용하고 메모와 읽기 전용 `source_location_note`에 공개 좌표 오차를 표시합니다. 대기함과 기록의 표시에서 이동된 점으로 장소명을 교정하거나 확정 행정구역을 만들지 않으며 도감의 확정 관찰 지역 근거에서도 제외합니다. 원본 좌표나 원문을 역으로 추측하지 않습니다. DB 테이블·스키마 버전은 유지합니다.

수집 진행 JSON의 `location_policy_version=3`로 새 기준의 검사 여부를 구분합니다. 이전 버전의 과거 수집 조건은 사용자가 다시 실행할 때 해당 조건만 처음부터 재검사하며, 관찰 번호 중복·삭제 보존·기존 등록 스냅샷 규칙은 유지합니다. 최신 수집의 기존 진행 위치는 초기화하지 않습니다.

스키마 버전 11의 collected_observations·collection_revisions·collection_imports를 그대로 사용합니다. source는 inaturalist이며 원문 API 응답은 payload_json의 original, 화면과 등록에 쓰는 값은 별도 필드로 저장합니다. 관찰자·라이선스·원문 시각·게시 시각·좌표 정확도·단계 주석을 원문에 보존합니다. 선택 등록은 source_type=indirect와 원문 URL을 저장하고 기존 도감 단계 추정·수동 수정 이력을 사용합니다. 네이처링 날짜 해석·국명 연결은 유지하고 iNaturalist에는 observed_on 날짜·명확한 현지 시각 및 학명 정확 일치를 사용합니다.

수집 진행 파일은 DB 옆의 `<DB 파일명>.inat-sync.json`입니다. 검색 방식·분류·지역·관찰 기간의 조합별로 cursor·완료 여부·완료한 신규 기준 번호·현재 진행의 최고 번호를 보존합니다. API는 ID 내림차순과 id_below로 과거를 잇고 신규 수집에는 id_above 완료 기준도 적용합니다. 첫 신규 수집은 같은 지역 과거 수집의 가장 이른 started_at을 created_d1으로 사용하여 과거 수집 중 새 게시물을 놓치지 않으며, 과거 수집 이력이 없을 때는 최신 200건으로 시작합니다. 페이지 전체의 DB 저장이 성공한 뒤 진행 파일을 임시 파일로 쓰고 원자적으로 교체합니다. 진행 저장 실패 시 앞서 저장한 페이지를 재조회할 수 있지만 출처별 관찰 번호 고유 제약으로 중복 행을 만들지 않습니다. 오류 응답과 잘못된 페이지 순서는 진행 위치를 갱신하지 않습니다. 다중 worker 실행은 검증하지 않았으며 현재 로컬 단일 백엔드 프로세스에서 요청 잠금으로 직렬 처리합니다.

최초 수집 전 SQLite backup API로 DB 보호 복사본을 생성하며 복사 실패 시 수집 자료 저장을 중단합니다. 스키마 이전과 새 의존성은 없습니다. 기본 DB와 진행 파일은 Git 제외 대상입니다. 수동 DB 복구 시 진행 파일을 별도로 보존하고 복구 DB와 진행 기준의 일치를 확인해야 합니다. 원본 DB나 진행 파일을 자동 삭제·초기화하지 않습니다.

## 논문과 간접 관찰 연결 · 버전 12

papers는 id·고유 identity·payload_json·최초 수집 시각을 저장합니다. DOI가 있으면 정규화한 DOI로 수집처 간 중복을 묶고 DOI가 없는 자료는 수집처와 원본 번호를 사용합니다. JSON은 제목·저자·학술지·제공된 정밀도의 발표일·언어·초록·원문 URL과 제공자별 원문 응답을 보존합니다. 갱신은 원문 이력을 추가하고 빈 필드를 보완하며 기존 관찰은 변경하지 않습니다. 논문 추천·AI 요약은 제공하지 않습니다.

paper_observations는 paper_id·observation_id·사용자 입력 evidence·등록 당시 source_snapshot·같은 입력의 중복 방지용 case_key·생성 시각을 저장합니다. 한 논문은 여러 관찰과 연결할 수 있습니다. POST /api/papers/{paper_id}/observations는 간접 관찰·종 선택·근거를 검증하고 기존 기록 저장 함수를 같은 트랜잭션으로 호출하여 관찰과 논문 연결을 함께 저장합니다. 실패하면 전체를 되돌립니다. 원문 관찰일·장소는 사용자가 입력하며 발표일을 관찰일로 복사하지 않습니다. 연결된 관찰을 직접 관찰로 변경할 수 없습니다. 원문과 최초 근거는 스냅샷으로 보존합니다.

휴지통 이동·복구는 연결을 유지하고 활성 사례 수만 목록에 표시합니다. 관찰 완전 삭제는 paper_observations 연결을 먼저 제거하고 논문 행은 보존합니다. 버전 11에서 12로 이전할 때 전체 DB의 before-v12 보호 복사본을 먼저 만들고 두 테이블·인덱스만 추가합니다. 기존 테이블·행·사진은 재작성하지 않으며 실패 시 새 테이블과 버전 변경을 롤백합니다. 원본 DB를 삭제·초기화하지 않습니다. 수동 복구는 서버를 중지하고 현재 DB를 보존한 뒤 보호 복사본을 별도 경로에서 확인합니다.

## 로컬 PDF 논문 추가 · 버전 13

논문 검색 박스의 KCI 안내 바로 위에 PDF 직접 추가 한 줄을 제공합니다. 파일당 20MB, 1~200쪽, 추출 텍스트 50만 자까지 허용하며 암호화·손상 파일은 거부합니다. 스캔 PDF의 원본은 보관하지만 OCR은 제공하지 않습니다. 제목은 파일명, DOI는 첫 쪽의 문자열을 사용하므로 원문 확인이 필요합니다. 파일 생성일을 발표일로 사용하지 않으며 저자·발표일을 추정하지 않습니다.

paper_files(id, paper_id, sha256 UNIQUE, original_name, pages_json, created_at)는 논문과 PDF 원본 및 쪽별 추출 텍스트를 연결합니다. 원본은 DB와 같은 폴더의 papers/해시.pdf에 그대로 보관하며 원래 파일을 변경하지 않습니다. 같은 파일은 해시로, 같은 논문은 DOI로 연결하고 기존 서지값은 덮어쓰지 않습니다. 보관 파일과 DB는 Git에서 제외됩니다. 업로드와 텍스트 추출은 로컬에서 처리하며 외부 API로 PDF를 전송하지 않습니다.

POST /api/papers/pdf는 원시 PDF 본문과 filename을 받으며 기존 로컬 화면 요청 검사를 적용합니다. GET /api/papers/pdf/{id}는 PDF 원문, GET /api/papers/pdf/{id}/text는 쪽별 텍스트를 반환합니다. 논문 목록의 files에 원문 연결을 제공합니다. 목록 수집처는 전체·Crossref·KCI·PDF를 구분하며 최초 발표 기간은 비어 있어 과거·발표일 미상의 PDF도 조회됩니다. PDF 선택 상태에서는 외부 논문 갱신을 실행하지 않습니다.

버전 12에서 13으로 이전할 때 before-v13 보호 복사본을 만든 후 paper_files와 인덱스만 추가합니다. 실패하면 새 테이블과 버전을 함께 되돌립니다. 이전 관찰과 도감은 재작성하지 않습니다. 원본 PDF와 보호 복사본을 함께 보존해야 파일까지 복구할 수 있습니다.

검토 후보 탭과 PDF 관찰 자동 추출·자동 등록은 제공하지 않습니다. 일반 PDF 추가는 논문만 저장하며 원문을 확인한 사용자가 기존 간접 관찰 등록으로 사례를 입력합니다. 별도로 사용자가 요청한 PDF의 수동 검토 반입은 보호 복사본과 반입 목록을 남기고 출처·근거·미검수 상태를 보존합니다.

휴지통의 새로고침 오른쪽에 전체 삭제를 제공합니다. 확인 화면에서 전체 항목 수와 복구 불가 안내를 읽은 후 실행합니다. DELETE /api/trash는 화면에서 확인한 모든 항목의 id·expected_deleted_at를 받아 현재 전체 목록과 일치할 때만 처리합니다. 새 삭제·복구 등으로 목록이 바뀌면 409로 중단합니다. 중첩된 탐사·관찰은 한 번만 처리하고, 보호 복사본 하나를 남긴 뒤 한 트랜잭션으로 삭제합니다. 보호 복사본 생성이나 삭제가 실패하면 전체 작업을 중단·롤백합니다. 사진 원본·논문·외부 수집 원문·소장 기록은 보존하며 소장과 연결된 관찰은 기존처럼 삭제를 거부합니다.


## 출현 행정지역 근거

species_references의 기존 JSON 구조를 확장하며 DB 테이블·버전은 변경하지 않습니다. region_evidence는 code(로컬 경계의 식별자), origin(excel/manual/observation), detail(원문 셀 또는 관찰 번호·실제 날짜·출처)을 담습니다. 저장 JSON에는 엑셀·수동 근거를 보존하고 관찰 근거는 활성 user_confirmed 관찰에서 일괄 계산합니다. region_codes는 합산 지역 코드이며 region_search에는 명칭·옛 명칭·권역 검색용 문자열을 반환합니다. 기존 regions 수동 원문은 별도로 보존합니다. region_unmatched에는 연결을 확정하지 못한 원문을 보존합니다.

내부 _region_exclusions는 사용자 체크 해제를 보존합니다. 참고자료 저장 시 화면의 합산 문자열이나 관찰 근거를 원문에 복사하지 않습니다. 선택 결과에 따라 수동 추가·제외를 처리하고 갱신 시각으로 기존 편집 충돌 검사를 유지합니다. 관찰 삭제·복구·종/장소/동정 변경은 다음 조회에서 합산 결과에 반영됩니다. 관찰 응답의 administrative_region과 administrative_region_code는 현재 경계에서 확인한 표시용 지역이며 원문 장소와 좌표를 바꾸지 않습니다.

행정경계는 SGIS 2025-06-30의 시도·시군구, WGS84 변환·표시용 경량화 자료입니다. 식별자는 해당 자료의 통계지역 코드이며 법정동 코드와 혼용하지 않습니다. 마라도와 한라산은 special-marado/special-hallasan 사용자 지정 지역입니다. 한라산의 경계는 해발 1,000m 이상으로 고도 격자에서 보간한 주 연결 영역입니다. 원본 파일 해시·출처·가공 방법은 GeoJSON과 assets/README.md에 보존합니다. 외부 서비스로 개인 관찰 좌표를 보내지 않습니다.
### 수집 자료의 종과 성장 단계 수정

수집 자료의 성장 단계 직접 지정은 기존 collected_observations.payload_json의 내부 _stage_override에 덮어씁니다. 새 테이블·열이나 별도 검수본은 만들지 않습니다. PUT /api/collection/{id}/stage는 stage·선택적 species_id와 expected_version을 받으며, version은 해당 JSON의 SHA256입니다. 동시 수정·원문 변경·등록 완료·삭제 상태는 409로 거부합니다. 선택적 species_id로 도감 종도 지정할 수 있으며 _species_override에 별도로 저장합니다. 원본 종·날짜·장소·출처는 덮어쓰지 않습니다. 등록 시 사용자 지정 종을 우선하며 두 수정값 모두 재수집 시 유지합니다. 재수집 시 수동 지정값을 유지합니다.

수집 목록의 stage_manual은 사용자 지정 여부입니다. 선택 등록 시 해당 단계를 사용하고 collection_imports.inference_json에 manual_stage_override와 original_inferred_stage를 남겨 도감 추정과 구분합니다. 수동 지정한 값 자체는 기존 자료에서 덮어쓰며 변경 이력을 별도로 쌓지 않습니다.

### 장소 원문과 정규화 표시

탐사·관찰 조회와 외부 수집 대기함 응답의 display_place는 표시용 장소, place_search는 원문과 행정지역 별칭을 합한 검색용 문자열, location_note는 확인 필요 사유입니다. 모두 조회 시 파생하며 새 DB 열이나 원문 덮어쓰기를 사용하지 않습니다. effective_place와 place_name/place_raw는 기존 원문 의미를 유지하므로 저장 기상의 조건 비교·중복 제거·외부 원문 변경 감지는 영향을 받지 않습니다.

현재 행정명 표시와 경계 자료의 기준일은 구분합니다. 2025 경계에서 개편 전 구역을 새 구역으로 나눌 수 없는 경우 추정하지 않습니다. 지역 코드도 원본 SGIS 코드로 유지하며 법정 행정구역 코드로 바꾸지 않습니다.

정확한 좌표가 없고 시·군·구 위치가 확인된 간접 관찰은 출처에 관계없이 지도에서 빨간 핀으로 표시합니다. 관찰 응답의 administrative_pin은 경계 중심에 가까운 내부 표시점이며 실제 관찰 좌표와 별개입니다. 위치가 공개되지 않았거나 도감의 참고 분포만 있는 경우에는 핀을 생성하지 않습니다.

사용자가 요청한 주소 검색과 좌표 주소 확인 결과는 로컬 DB의 map_lookup_cache에 저장합니다. 같은 입력은 저장된 응답을 사용하며, 선택해 적용한 후보는 기존 기록의 위치 필드에 저장합니다.

### 관찰 지역의 지도 표시 단위

검수 후 등록한 관찰 근거는 시·군 전체에 적용합니다. 구로 나뉜 일반 시는 같은 시의 모든 구 경계에 적용하고, 특별시·광역시·세종은 해당 시 전체 경계를 사용합니다. 도 전체로 확대하지 않습니다. 원본 좌표·장소 및 마라도·한라산 특별 경계 판정은 유지합니다. 도 전체 참고 경계가 있어도 관찰 시·군 경계는 진한 녹색으로 표시합니다. 미발견·대기 자료·휴지통 자료는 관찰 근거에서 제외합니다.


### 종별 세부 정보

종 참고자료의 JSON에 details 배열을 추가합니다. 기존 자료에 없으면 빈 배열로 응답하며 DB 일괄 변환은 필요하지 않습니다. 기존 other_notes와 ecology_source는 기존 기타 원문·출처를 보존합니다. 이전 클라이언트가 details를 생략한 저장 요청을 보내면 기존 배열을 유지합니다. 빈 배열을 명시하면 세부 정보 사례만 제거합니다.

details는 최대 100건입니다. 각 사례의 id는 종 안에서 고유해야 합니다. category는 host_rearing, activity, traits, diapause, rearing, breeding, specimen, memo 중 하나입니다. title은 1~200자, body는 1~5000자, source는 1~2000자입니다. evidence는 field, rearing, literature, inferred 중 하나이고 기본값은 literature입니다. scope와 timing은 각각 최대 500자의 선택 입력입니다. 개인 표본·사육 개체 기록과 구분한 종별 참고 자료이며 관찰 통계로 자동 편입하지 않습니다.

기주식물(사육)의 host_rearing 사례는 title에 식물 이름을 저장하며 body는 비울 수 있습니다. 다른 항목의 body는 필수입니다.


### 모바일 사진 대기함과 연결 정보 · DB v14

기존 테이블은 유지하고 mobile_settings, mobile_sessions, mobile_limits, mobile_photos 및 대기 상태 인덱스를 추가합니다. 버전 이전은 기존 SQLite 보호 복사본 생성 후 한 트랜잭션으로 수행합니다. 실패 시 버전·추가 테이블이 함께 되돌아갑니다. 이전 버전 실행 파일로 되돌릴 경우 서버를 중지한 뒤 보호 복사본으로 복구해야 하며 이전 이후 새로 들어온 자료는 별도 보존해야 합니다.

mobile_settings는 전송 허용 여부와 일회용 연결 코드의 SHA-256·만료 시각을 보관합니다. mobile_sessions는 기기명·발급 시각·만료 시각과 세션 토큰의 SHA-256만 보관합니다. 실제 토큰은 Secure·HttpOnly·SameSite=Strict 쿠키로만 전달합니다. 연결 코드는 10분·한 번, 세션은 최대 30일이며 PC에서 기기별 또는 전체 해제합니다. mobile_limits는 로그인·전송의 기간별 요청 수를 보관합니다.

mobile_photos는 파일 SHA-256 고유 키, 추출 원문과 한국 시각 입력 후보의 JSON, 전송 기기명·수신 시각·pending/registered/discarded 상태·연결 탐사 번호를 저장합니다. 수신만으로 photos·surveys·observations에 편입하지 않습니다. 같은 파일 재전송은 기존 상태를 반환하고 삭제한 대기 자료를 되살리거나 등록한 관찰을 다시 만들지 않습니다. 서로 다른 사진은 자동으로 같은 관찰로 합치지 않습니다.

PC에서 선택한 사진을 같은 탐사로 검수 등록할 때 기존 photos의 해시를 재사용하거나 메타데이터 전용 항목을 만들고 탐사 공통 photo_ids에 연결합니다. 이때 observations는 비어 있으며 이후 기존 탐사 수정 API로 여러 직접 관찰을 추가합니다. 사진 촬영 시각을 관찰 시각으로 자동 복사하지 않습니다. 기존 클라이언트의 직접 관찰 한 건 등록 요청과 종별 사진 연결은 호환을 유지합니다. 사진 연결·탐사 저장·대기함 상태 변경은 같은 트랜잭션입니다. 종·성장 단계·날짜·장소·좌표는 검수값이며 사진별 원문을 덮어쓰지 않습니다. 휴대폰이 추출한 값은 PC에서 사진 원본을 검증한 결과와 구분하여 provenance에 기록합니다. GPS 없는 사진도 수신할 수 있고 등록 전 사용자가 위치를 입력해야 합니다.


### 집 안 입력·외부 조회 분리

mobile_* 테이블은 집 안 사진 전송용으로만 사용합니다. 주소는 data/mobile-lan.json의 지정된 내부 IP와 허용 네트워크로 제한합니다. 외부 도메인의 서버는 원본 DB에 연결하지 않습니다.

외부 조회 인증은 별도 계정 실행 폴더의 auth/viewer.sqlite3에 코드 해시·세션 해시·요청 제한만 보관합니다. 원본 관찰 테이블과 사진 파일은 이 인증 DB에 없습니다. snapshots/current.json은 PC 사용자의 명시적 갱신 시 등록 관찰·도감·소장을 내보낸 읽기 전용 사본입니다. 한 읽기 트랜잭션으로 만들고 임시 파일에서 교체하므로 실패 중에는 이전 사본을 유지합니다. 대기 수집 자료·원본 이미지·PC 키·API 설정은 제외합니다.

PC API 인증 키와 조회 서버 실행 자격은 Git 제외 data에 저장하며 조회 계정은 읽을 수 없습니다. 조회 실행 자격은 Windows DPAPI로 현재 사용자에 묶입니다. 원본 DB와 프로젝트의 계정별 ACL을 적용하므로 원본 코드만 되돌리는 것으로 접근 권한이 복구되지는 않습니다.


### 한살이 관찰 통계와 표시 계산

`frontend/src/lifeCycle.ts`의 collectLifeSamples → observationGroups → boxStats/densityShape 순서입니다. 종·단계·실제 날짜·장소·좌표·출처 종류·출처 근거로 중복을 묶습니다. 직접 관찰은 탐사 번호, 간접 관찰은 출처 문자열을 근거로 사용합니다. 개체 수·사진 수로 가중하지 않습니다. 사용자 확인 관찰과 이전 형식의 검수된 간접 관찰 호환 조건을 적용하며 단계 미상·미발견은 제외합니다.

연간 날짜를 윤일 포함 366일 축에 놓고 가장 긴 관찰 공백 직후부터 펼칩니다. 공백의 중간을 나누거나 도감 발생 구간별로 배분하지 않습니다. 선택 조건의 모든 사례를 하나의 분포로 계산합니다. 20사례 이상은 선형 보간 Q1·중앙값·Q3와 1.5 IQR 안의 관측값 양끝을 수염으로 사용합니다. 그 밖의 실제 사례는 이상값 점으로 남깁니다. 통계적 이상값은 오류 판정이 아닙니다.

표시 밀도는 모든 해당 사례에 14일 Gaussian 평활화를 적용하고 원형 거리로 연말을 잇습니다. 수염 밖 곡선은 숨기며 단계별 최대 높이를 정규화합니다. Q1~Q3의 가로 구간만 채우고 중앙값 선은 곡선 안에 제한합니다. 가운데 가로 연결선은 없으며 사분위 밑변·경계선·수염 끝·이상값은 유지합니다. 채움 면적이 전체 확률의 50%라는 뜻이 아닙니다. 피크는 관찰 시기 집중을 보여줄 뿐 세대 수·개체 수·발생 확률이 아닙니다. DB·관찰 날짜를 변경하지 않는 화면 계산입니다.


Android 집 안 전송 앱은 기존 PhotoMetadata JSON과 DB v14를 재사용하며 스키마를 추가하지 않습니다. 사진 원본·미리보기·기기 URI·연결 코드를 mobile_photos에 추가하지 않습니다. 선택과 추출 결과는 앱 메모리에만 있고 토큰·만료 시각만 Keystore AES-GCM으로 암호화해 백업 제외 영역에 저장합니다. 회전 미지정 EXIF 값 0은 표시용 기본 방향 1로 정규화하고 경고를 보존하며 촬영 시각·GPS는 추측하지 않습니다.

관찰 상세는 탐사·관찰 정보와 오른쪽 사진을 연한 노란 둥근 박스로 분리합니다. 상단은 탐사 전체 삭제·기록 수정·닫기 순서이며 기본 초점은 닫기입니다. 개별 관찰 삭제는 해당 관찰 아래쪽에 있습니다. 학명은 종명 아래, 좌표는 주소 다음 줄에 표시하고 시각은 분까지만 표시하며 저장 원문은 보존합니다. 관찰·탐사·소장 표는 밑줄 없이 한 번 클릭 선택, 더블클릭 상세 열기를 사용합니다.
사진 원본·해시·EXIF는 보존합니다. 표시용 /api/photos/{id}/display는 원본이 있는 경우 긴 변 1920px 이하의 EXIF 없는 WebP 사본을 data/photo/display에 생성·재사용합니다. 기존 JPEG 미리보기 경로는 호환성을 유지합니다. 탐사·소속 관찰에 연결된 고유 사진은 합계 3장까지 새로 연결하며 기존 3장 초과 자료의 동일 연결·감소는 허용합니다. DB 스키마는 변경하지 않습니다.

스키마 15는 tags.category(environment/individual) 열을 추가합니다. 기존 태그 번호·탐사·관찰 연결과 이름은 보존하며 사육·돌연변이의 기존 지정 이름만 individual로 분류합니다. 분류 이동은 전역이며 연결 자료를 삭제하지 않습니다. 관찰 입력은 같은 연결 목록을 환경·개체로 나누어 표시하고 탐사 공통 개체 태그는 관찰에 상속됩니다. 도감 JSON은 representative_photo_id와 stage_identification(stage,points,source,photo_ids)을 추가하며 이전 클라이언트의 생략은 보존합니다. 사진 번호 존재·단계 중복·설명 출처를 검증합니다. 이전 전 전체 SQLite 보호 복사본을 만들고 실패 시 트랜잭션을 되돌립니다. 복구는 서버를 종료한 뒤 현재 자료를 별도로 보존하고 보호 복사본을 별도 경로에서 확인합니다.

스키마 16은 논문별 즐겨찾기·태그, 직접 입력한 웹 원문과 관찰 연결, Gemini 일일 호출 수를 별도 테이블에 보관합니다. 이전 전에 SQLite 보호 사본을 만듭니다. 화면에서 Gemini 서지 추출을 실행하면 유효한 값을 자동 저장합니다. 공란과 동일 연도의 상세 날짜는 기존 값을 유지하고, 변경 항목에는 원래 값과 사용한 PDF 번호를 남깁니다. 기존 논문 식별자와 출처는 보존합니다. 웹 원문은 주소와 관련 종의 조합으로 중복을 확인합니다.


스키마 17은 collection_import_views(item_id, observation_id, payload_json, inference_json)를 추가합니다. 등록 원문과 당시 도감 근거의 저장 위치는 기존 collection_imports입니다. 파생 payload는 출처·공개 위치 오차와 흐림 여부·좌표·원문 장소·기상·관찰시각·URL만, 파생 inference는 stage와 manual_stage_override만 가집니다. 부모 item_id 외래키와 삭제 연동을 유지하며 삽입·원문 또는 추정 정보 수정 트리거가 같은 트랜잭션에서 요약을 갱신합니다. 원본 보존용 JSON과 과거 근거는 축약하지 않습니다. 현재 수집 대기 자료의 원문과 등록 당시 원문은 계속 구분합니다. v16에서 보호 복사본 후 기존 등록 자료의 요약을 생성하고 실패하면 스키마·요약 생성을 모두 되돌립니다. 복구 시 현재 자료를 별도 보존하고 보호 복사본을 별도 경로에서 확인하며 실행 중인 DB 위에 덮어쓰지 않습니다.

스키마 16용 이전 코드는 v17 DB를 직접 열 수 없으므로 코드만 되돌려 운영하지 않습니다. 복구 시 서버를 중지하고 현 DB를 보존한 뒤 보호 복사본을 별도 경로에서 검사합니다.
