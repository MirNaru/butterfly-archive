# 미구현 및 확인 사항

현재는 종 수동 등록·목록, 탐사·종별 기록 등록·수정·목록·상세 조회, 관찰·탐사 통합 검색, 직접·간접 출처 입력, 통합 관찰 기록표와 하단 탭을 구현했습니다. 나비 도감의 한살이 도표·습성 메모와 환경 태그 등록·수정·검색도 구현했습니다. 사진 검사·정보 등록·선택 원본 보관·기록 연결과 소장·취득 경로 관리도 구현했습니다. 탐사·관찰의 휴지통 삭제·복구도 구현했습니다. 네이버 지도·주소 선택과 ASOS 기상 조회·저장을 구현했습니다. 네이처링 Chrome 확장 수집·DB 전송·사용자 선택 등록, 원문 기상 표시, 관찰 상세 팝업 내 수정과 20사례 기준 한살이 상자 수염도 구현했습니다. 아래는 미구현 작업과 아직 결정되지 않은 항목을 관리하는 목록입니다. 해결 시 현재 사양 문서에 반영하고 이 목록을 정리합니다.
나비 도감의 설명을 동일한 규격, 어순, 단어등으로 통일 시켜야 합니다.

## 사용 흐름 점검 범위

- 별도 시험 DB와 외부 API를 끈 화면 서버에서 새 탐사 등록 → 합성 JPEG 촬영 정보 검사·날짜 적용·정보 등록 → 탐사 저장 → 검색의 정상·빈 결과 → 관찰 상세 팝업 내 단계·개체 수·메모 수정 → 개별 관찰 휴지통 이동·복구 → 화면 새로고침 후 재조회를 확인했습니다. 수정 내용과 사진 정보 연결을 보존했습니다.
- 관련 API 검사 70개와 검색·필터 검사 12개를 통과했습니다. API 검사에는 잘못된 입력·저장 실패·편집 충돌·기상 조회 실패 시 기존 자료 보존·삭제 후 연결 보존·재시작 후 조회가 포함됩니다. 실제 개인 DB와 실제 외부 API를 사용하지 않았습니다.
- 이번 화면 점검은 시험 기록 한 건의 흐름을 확인한 것입니다. 수백 건 화면 성능, 실제 지도 SDK와 기상청 추가 호출, 서로 다른 사진 1400장의 처리 성능은 이번 검증에 포함하지 않았습니다. 한살이의 시기 밖 실제 자료 확인도 별도로 남아 있습니다.

## 보류 및 후속 범위

- 도감 기간의 일 단위 경계와 초중·중후 편집을 구현했습니다. 제공 자료가 없는 종의 기간 입력과 도감명·판본 확인은 남아 있습니다. 관찰 날짜는 보정하지 않습니다.

- 환경 태그 이름 변경·통합·삭제 관리와 관찰별 구조화된 생태 항목은 후속 범위입니다. 현재는 태그 선택 해제만 지원하며 기억된 이름은 유지합니다. 태그는 자동으로 습성·기상 수치로 변환하지 않습니다.

- 근거 불명의 기존 채집 가중치는 원본만 보존하고 기본 추천에 사용하지 않습니다. 분포 상수와 과거 연도 기준의 근거는 미확인입니다.
- 표 셀 직접 편집, 일괄 붙여넣기, 대량 수정은 별도 승인·검증 대상으로 둡니다.
- 전체 변경 이력 열람, 자동 백업, 엑셀 내보내기의 구체 범위는 확정하지 않았습니다.
- 등록 요청 도중 응답이 끊긴 경우 서버에 저장되었을 수도 있으므로 목록을 조회한 뒤 재시도하도록 안내합니다. 요청 중복 방지 키는 아직 구현하지 않았습니다.
- 탐사 목록은 일괄 조회 방식이며 합성 자료 300·1000건에서 측정했습니다. 1000건 수정창 진입·상세 닫기는 자동화 포함 중앙값 0.69초·0.64초로 추가 개선 여지가 있습니다. 페이지 처리·실제 지도 SDK·장시간 메모리는 후속 검증 대상입니다.
- 탐사·관찰 수정과 휴지통 삭제·복구를 구현했습니다. 휴지통 항목별 완전 삭제도 구현했습니다. 휴지통 일괄 비우기·소장·종 정보 삭제는 후속 범위입니다.
- 네이처링 수집·선택 등록은 구현했습니다. iNaturalist 공식 API 수집은 구현했으며 구글링 수집, 논문 서지 수집·간접 관찰 사례 등록도 구현했습니다. 자동 진위 검증·출현 예측은 후속 단계입니다. 모바일 사진 정보 전송은 첫 버전을 구현했으며 HTTPS 발급·실기기 검증이 남았습니다.
- Starlette TestClient의 httpx 사용 중단 예정 경고가 테스트에서 계속 발생합니다. 의존성 변경 없이 테스트는 통과하며, 대체 패키지 적용은 별도 검토 대상입니다.

네이처링 확장은 사용자가 시작한 연속 수집과 로컬 전송을 지원합니다. 수집 원문은 대기함에 보존하고 체크한 항목을 간접 관찰로 등록합니다. 게시자가 위치를 숨겼거나 위치가 미입력·빈칸이거나 공개 좌표 쌍이 없는 자료는 수집에서 제외합니다. 등록 후 대기 목록에서 숨기며 관찰 삭제·복구는 휴지통에서 처리합니다. 단계는 도감 기간에 따른 추정과 수동 확인을 구분하며 자동 진위 검증은 구현하지 않았습니다.

## 화면 성능 개선 검증

- Windows PC(Ryzen 7 5800X), Codex 브라우저 1280×720, Vite 개발 모드에서 동일한 합성 관찰 300·1000건과 282종으로 비교했습니다. 아래는 각 5회 중앙값이며 자동화 명령과 DOM 결과 확인 시간을 포함합니다. 실제 입력·화면 그리기 지연만을 측정한 값은 아닙니다.

| 초기 표시 | 0.630 → 0.579초 | 1.520 → 0.823초 |
| 상세 열기 | 0.373 → 0.270초 | 0.819 → 0.301초 |
| 수정창 진입 | 0.354 → 0.364초 | 0.776 → 0.691초 |
| 상세 닫기 | 0.343 → 0.340초 | 0.772 → 0.638초 |

- 1000건 탐사 API 중앙값 316.5 → 37.6ms, 저장 기상 API 202.9 → 13.5ms입니다. 탐사 SELECT는 7001 → 5회, 저장 기상 SELECT는 901 → 1회이며 두 경로 모두 DB 연결 한 개를 사용합니다. 300·1000건의 탐사·저장 기상 응답은 변경 전 저장본과 완전히 같았습니다.
- 도감 전체 282종 행·텍스트는 유지하고 화면 주변 그래프만 생성합니다. 최초 화면의 그래프 282 → 6개, 전체 DOM 요소 약31493 → 8826개를 확인했습니다. 세로 이동 뒤 해당 구간 그래프 9개, 가로 스크롤 양 끝 이동, 편집 저장 후 탭을 바꿨을 때 최신값 표시를 확인했습니다.
- 1000건 검색 재측정은 약443ms, 해제260ms, 날짜 정렬229ms였습니다. 검색에는 행 수 도달 대기가 추가되어 이전 측정과 직접 비교에 한계가 있으므로 검색 성능 개선을 주장하지 않습니다.
- 실제 개인 DB를 테스트로 수정하지 않았고 외부 API 호출은 0회입니다. 실제 지도 SDK, 사진1400장, 장시간 메모리·프레임 속도, 배포 빌드 실행 성능은 미검증입니다. 측정 원본은 Git 제외 경로 `.tmp/performance-20261030-run2`의 이전·이후 보고서에 보관합니다.

논문 수집은 Crossref를 기본으로 사용하며 KCI는 선택 연동입니다. KCI 실제 키를 사용한 응답 검증과 대량 논문 목록 성능은 별도 확인 대상입니다. 추천·AI 요약·본문 자동 분석·관찰 정보 자동 추출은 제공하지 않습니다.

로컬 PDF 직접 추가·원본 보관·쪽별 텍스트 열람을 구현했습니다. PDF에서 생물학적 관찰 사례를 자동 해석하는 기능, OCR, AI 요약·추천은 구현하지 않았습니다. 파일명·첫 쪽 DOI로 얻는 서지정보는 원문 확인이 필요하며 발표일을 파일 생성일로 대체하지 않습니다.

출현지역의 로컬 경계는 SGIS 2025-06-30 기준입니다. 현재 명칭 표시는 별도로 보정하지만 이후 분구·통합의 새 경계 전체를 반영한 자료는 아닙니다. 특히 인천 옛 중구·서구의 세부 지역은 확인 필요로 표시하며, 최신 공식 경계 확보 후 대조가 필요합니다. 경계 인접 좌표의 정밀 판정과 해외 행정지역의 한국어 변환도 검증 범위에 포함하지 않습니다.

## 출현지역 레이어 성능 검증

시간은 화면 내 동작 시작부터 마지막 도형 변경을 반영한 프레임까지의 대용 지표이며, 최초 표시에는 로컬 API 요청을 포함합니다. 측정 종료를 확인하는 700ms 대기와 도구 왕복 시간은 제외했습니다. 지도 타일 전체 다운로드 완료 시간이나 모든 사용자 환경의 지연을 보장하는 값은 아닙니다.

## iNaturalist 수집 크기와 기록 연결 점검

- 공식 공개 API의 대한민국 나비 최신순 조회를 저장 없이 비교했습니다. 기존 200건 요청은 읽기 한도 12,000,000바이트를 넘었고(12,000,001바이트까지 읽고 중단), 50건 요청은 2,973,173바이트·약 2.50초로 정상 응답했습니다. 모든 종·시점에서 같은 응답 크기나 성공을 보장하는 값은 아닙니다.
- 50건씩 저장·재개하고, 최초 최신 200건 종료 조건을 네 번의 요청에 맞췄습니다. 일시 오류 재시도는 한 번으로 제한하고 429·일일 한도는 유지합니다. 200건 시험은 한도 초과 여부만 확인했으며 불완전 JSON의 건수를 해석하지 않았습니다. 두 확인 모두 개인 DB에 자료를 반입하지 않았습니다.
- iNaturalist 관련 21개 모의 API 테스트에서 첫 200건 분할·ID 커서·중복 방지·재시도 시도별 사용량·반복 실패와 진행 보존·429 중단을 확인했습니다. 실제 전체 과거 수집·장시간 연속 수집은 미검증입니다.
- 실제 앱에서 청띠제비나비의 네이처링 핀을 선택하고 위치 기록을 더블클릭해 동일 탐사 상세가 열리고 기록 탭·탐사 목록으로 전환되는 것을 확인했습니다. 개인 기록은 수정하지 않았습니다. 수집 대기함이 비어 있어 긴 주소는 임시 합성 화면으로 페이드·좌표·출처 표시를 확인했습니다.
- 최종 백엔드 236개 테스트와 TypeScript 검사·빌드가 통과했습니다. 린트 오류는 없으며 기존 CollectionInbox 경고와 Starlette TestClient 경고는 유지됩니다. 수정된 백엔드를 로컬 서버에 적용했습니다.


### 기록 표시 열 변경 검증

개발 모드의 실제 관찰 1,177건으로 Codex 브라우저에서 환경 태그·성장 단계·메모 열을 선택했습니다. 변경 전에는 도감 참고 행 포함 1,445행을 그렸고 조작 소요 시간은 각각 434·335·452ms, 변경 후에는 실제 기록 중 최대 48행을 그리며 277·287·289ms였습니다. 자동화 조작 대기를 포함한 측정으로 순수 렌더링 시간은 아닙니다. 표시 열 18개 연속 선택, 마지막 행 스크롤, 검색 시 처음으로 이동, 72px 동일 행 높이를 확인했습니다. 사용자 환경의 응답 없음 현상이 모든 상황에서 재현·해소됐다는 의미는 아니며 장시간 사용은 별도 검증 대상입니다.

### 모바일 전송의 남은 검증

- archive.mirnaru.kro.kr 최초 인증서 발급 시 kro.kr 공용 한도가 적용되었습니다. Let's Encrypt 응답의 재시도 가능 시점은 2026-11-04 11:03:43 KST였으며 실제 발급 시각은 보장하지 않습니다. ZeroSSL 전환은 사용자가 취소했습니다. 이후 사용자가 외부 포트를 닫았고 외부 HTTPS도 중지했습니다. 외부 조회만 이후 사용자 요청 시 다시 발급·연결을 검사합니다.
- S23 Ultra의 삼성 갤러리·JPEG/PNG 원문 EXIF 유지·집 안 전송·화면 잠금·장시간 전송을 확인해야 합니다. HEIC·원본/작은 사진 전송·백그라운드 자동 수집·브라우저 종료 후 전송 대기 보존은 현재 구현 범위에 포함되지 않습니다.
- 합성 사진으로 브라우저 로그인→촬영 원문 추출→전송→PC 대기함→종·단계 검수→직접 관찰 등록→기록 탭 즉시 반영을 시험 DB에서 확인했습니다. 개인 DB에는 시험 관찰을 만들지 않았습니다.


### 입력·조회 분리 검증 및 남은 확인

원본 DB·PC 인증 키 읽기, 조회 사본·서버 코드 쓰기, 직접 및 Vite 경유 PC API 호출이 실제 제한 Windows 계정에서 차단됨을 확인했습니다. PC 인증 키가 Vite의 파일 URL로 제공되지 않음도 확인했습니다. 합성 사본으로 브라우저 로그인·검색·성장 단계 필터·도감 세부 내용·소장 조회·로그아웃을 확인했습니다. 백엔드 252개·프론트엔드 48개 테스트와 빌드를 통과했습니다. 전체 보안 침해 가능성을 전수 검증했다는 뜻은 아닙니다.

실제 S23 Ultra에서 이중 공유기 너머 내부 HTTPS 인증서 경고까지 도달하는 것을 사용자가 확인했습니다. 휴대폰의 로컬 CA 신뢰 등록과 실제 갤러리 파일 전송은 남아 있습니다. 외부 공인 HTTPS·모바일 데이터망에서 조회 인증과 쓰기 차단 확인도 남아 있습니다. 인터넷 80·443은 현재 닫아둔 상태를 유지합니다.
