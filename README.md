# Butterfly Archive

나비 출현 기록 및 추적 시스템입니다. 현재는 종 수동 등록, 조사와 여러 종별 기록의 등록·수정·목록·상세 조회, 간단한 검색과 조사 표를 사용할 수 있습니다. 네이버 지도·주소 검색과 기상청 ASOS 자료의 조회·저장도 사용할 수 있습니다. 환경 태그의 공통·개별 선택과 사용자 항목 기억, 통합 검색·필터, 나비 도감과 한살이 도표도 사용할 수 있습니다. 삭제·복구, 사진, 일반 엑셀 반입 화면과 소장 관리는 아직 구현되지 않았습니다.

## 설치 환경

- Windows 10 64비트
- Node.js 24.22.1, npm 11.19.1
- Python 3.13.15, SQLite 3.50.4
- Git 2.55.0.windows.5, GitHub CLI 2.103.0
- React 19, TypeScript 6, Vite 8, FastAPI
- 정확한 패키지 버전은 frontend/package-lock.json과 backend/requirements*.txt에 기록합니다.

## 구조

- frontend/src: 기록 등록·조회, 지도·위치 선택, 저장 기상 화면과 API 호출
- frontend/vite.config.ts: 개발용 API 프록시
- backend/app: 기록 API, 지도·기상 연동, 호출 제한과 SQLite 저장
- backend/tests: API 성공 및 실패, SQLite 읽기와 쓰기 테스트
- backend/.venv: 프로젝트 전용 Python 가상환경, Git 제외
- data: 로컬 데이터베이스와 개인 관찰 자료, Git 제외
- .env.example: 비밀 값이 없는 환경변수 예시

## 처음 설치

새 PowerShell을 열고 프로젝트 루트로 이동하세요. 설치 직후 기존 터미널에는 PATH 변경이 반영되지 않을 수 있습니다.

```powershell
py -3.13 -m venv backend/.venv
.\backend\.venv\Scripts\python.exe -m pip install -r backend/requirements-dev.txt
cd frontend
npm.cmd ci
cd ..
```

실행만 필요한 경우 requirements-dev.txt 대신 requirements.txt를 사용하세요.
가상환경 활성화는 필요하지 않으며 PowerShell 실행 정책을 변경하지 않습니다.

프로젝트 루트에서 첫 번째 PowerShell:

```powershell
.\backend\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000 --reload
```

프로젝트 루트에서 두 번째 PowerShell:

```powershell
cd frontend
npm.cmd run dev
```

- 화면: http://127.0.0.1:5173/
- API 문서: http://127.0.0.1:8000/docs
- 상태 API: http://127.0.0.1:8000/api/health
- 하단 나비 기본 정보 탭에서 종을 등록하고 출현·분포·출처 등을 편집합니다. 동정 미확정 상태로도 관찰 기록을 저장할 수 있습니다.
- 하단 지도 / 표 / 나비 기본 정보 탭에서 화면을 전환합니다. 지도 탭을 처음 열 때만 지도를 생성하며 탭 전환 시 유지합니다.
- 새 조사와 기록 수정은 기존 화면 위의 중앙 창에서 진행합니다. 조사 공통 정보와 선택한 종별 기록을 함께 보여주며 여러 종별 기록은 선택창으로 전환합니다. 전환한 항목의 입력도 모두 함께 저장됩니다. 좁은 화면에서는 창 내부 스크롤을 사용합니다.
- 중앙 입력창은 Codex 브라우저의 1280×720 화면에서 채집 수량을 포함한 기본 입력 배치를 확인했습니다. 별도 시험 DB에서 여러 항목 저장·재조회, 숨겨진 항목의 필수값 검사, 취소 후 작성 계속, 위치 선택 보조창 닫기 및 기본 정보 등록·편집·재조회를 검증했습니다. 이 화면 변경 검증에서는 외부 지도·기상 API를 추가 호출하지 않았습니다.
- 각 터미널에서 Ctrl+C로 서버를 종료합니다.

프론트엔드는 /api/health를 호출하고 Vite가 8000 포트의 FastAPI로 전달합니다.
이 프록시는 개발 서버 전용입니다. 향후 배포 시 API 연결 구성을 별도로 정해야 합니다.
두 서버 모두 이 PC의 로컬 주소에만 바인딩합니다.

## 환경변수와 개인 데이터

기본 설정으로 바로 실행할 수 있습니다. 변경이 필요하면 .env.example을 .env로 복사하세요.
.env는 백엔드에서 자동으로 읽으며 기존 프로세스 환경변수를 우선합니다.
BUTTERFLY_DB_PATH는 프로젝트 루트를 기준으로 해석합니다.
기본 데이터베이스는 data/butterfly.sqlite3이며 서버 시작 시 생성됩니다.
서버 시작 시 스키마 버전 5를 적용합니다. 기존 자료를 같은 폴더의 .before-v5-시각.bak로 먼저 백업하고 태그 테이블을 추가합니다. 이전 버전의 필요한 변경도 함께 수행하며 실패하면 전체 이전을 되돌립니다. 기존 DB를 삭제하거나 초기화하지 않습니다.

기본 API는 GET/POST `/api/species`, GET/POST `/api/surveys`, GET `/api/surveys/{id}`입니다. PUT `/api/surveys/{id}`로 조사와 종별 기록을 함께 수정합니다. 삭제 API는 아직 없습니다. 기존 서버가 실행 중이면 종료 후 위 명령으로 다시 실행해 주세요.

검증에는 `.tmp/browser-check.sqlite3`를 사용하는 별도 서버를 사용했습니다. 이 파일의 가상 기록은 개인 DB로 복사하지 않습니다. 다른 포트로 검증하려면 백엔드의 `BUTTERFLY_DB_PATH`와 프론트엔드 프로세스의 `BUTTERFLY_API_TARGET`을 명시적으로 지정합니다. 기본값은 기존 8000 포트입니다.

개인 관찰 기록, 사진, 가져오기 및 내보내기 자료는 data, observations, imports, exports 폴더에 보관하세요.
이 폴더들과 SQLite 파일, 가상환경, 의존성, 임시 파일, .env, 인증키 파일은 Git에서 제외합니다.
.gitignore는 임의의 소스 파일에 직접 입력한 비밀 값이나 개인 데이터를 자동으로 판별하지 못합니다.
API 키를 소스 코드에 넣지 마세요. 프론트엔드에 전달하는 환경변수도 비밀 저장용으로 사용하지 마세요.

SQLite 쓰기 테스트는 임시 데이터베이스에서 수행하며 개인 데이터베이스를 수정하지 않습니다.
현재 Starlette TestClient에서 httpx 사용 중단 예정 경고가 발생하지만 테스트는 통과합니다.

현재 백엔드 자동 테스트는 84건이며 실제 외부 호출을 차단한 임시 DB에서 검사합니다. 호출 한도·동시 요청·재시작, 실패 시 기존 기상 보존, 자료 재사용, 날짜·시각 상속과 변경 감지, 버전 1 이전·실패 복구를 포함합니다. 공개 서울시청 위치의 실제 지도·주소 검색·좌표 주소 확인과 서울 관측소의 2025-10-22 일자료·12시 시간자료를 검증했습니다. 브라우저에서 핀 선택·숨김·복구, 검색 필터, 지도·표 전환, 주소 적용과 지도 클릭을 확인했습니다. 수백 건 성능, 사진, 삭제·복구는 미검증·미구현 범위입니다.

2026년 10월 24일 마무리 검증에서 자동 테스트 43건, TypeScript 검사, Vite 빌드, 린트가 통과했습니다. 실제 사용 DB의 버전 2 적용과 변경 전 백업을 확인했으며, 지도·표 왕복 시 지도 생성 수가 증가하지 않았습니다. 기상은 추가 외부 조회 없이 기존 검증 결과와 저장·재사용 테스트로 확인했습니다. 키·DB·백업은 Git 제외 상태이며 커밋·푸시는 수행하지 않았습니다.

스키마 변경이 실패하면 변경 트랜잭션은 되돌아갑니다. 백업 복원이 필요한 경우 서버를 종료하고 현재 DB와 백업을 모두 보존한 상태에서 복원 대상을 먼저 확인하세요. 새로 등록한 자료가 있는 DB 위에 이전 백업을 무조건 덮어쓰지 마세요. 사용자용 백업·복원 화면은 후속 구현입니다.

## 의존성 관리

- 프론트엔드: package.json과 package-lock.json을 함께 관리하고 재설치는 npm.cmd ci를 사용합니다.
- 백엔드: requirements.in은 직접 사용하는 실행 의존성, requirements-dev.in은 테스트 의존성을 설명합니다.
- requirements.txt와 requirements-dev.txt는 전이 의존성까지 고정한 설치 목록입니다.
- 의존성 변경 시 깨끗한 가상환경에서 실행 의존성을 먼저 설치하고 pip freeze로 requirements.txt를 갱신합니다. 이어 테스트 의존성을 설치한 뒤 requirements-dev.txt를 갱신하고 테스트합니다.

## 지도와 기상 사용 방법

지도 위의 **핀 숨기기** 오른쪽에서 **일반지도 / 위성지도**를 전환할 수 있습니다. 현재 지도 객체의 유형만 바꾸므로 별도 지도 생성 요청을 보내지 않습니다. 지도 영역은 브라우저의 남은 높이를 채우며 좌우·하단 여백을 맞춥니다. 위성 유형은 [네이버 지도 공식 SDK](https://navermaps.github.io/maps.js.ncp/docs/tutorial-MapTypes.html)의 기본 기능을 사용하며 기존 Dynamic Map 설정·한도를 유지합니다.

1. `.env`에 기존 키를 보관합니다. 대표 계정의 무료 적용과 네이버 콘솔의 API별 강제 사용 제한을 확인한 뒤 `MAPS_ENABLED=true`, `MAPS_FREE_TIER_CONFIRMED=true`, `KMA_ENABLED=true`로 활성화합니다. 예제 파일은 기본 비활성 상태입니다. 설정 변경 후 백엔드를 다시 시작합니다.
2. 조사 등록에서 **지도·주소로 위치 선택**을 열고 주소 검색 결과나 지도 클릭 위치를 선택한 다음 **이 위치 적용**을 누릅니다. 주소 없는 위치는 좌표만 적용할 수 있습니다. 직접 입력도 가능합니다.
3. 기록을 저장한 다음 상세의 **기상**을 열어 **관측소 찾기 → 관측소 선택 → 기상 조회하여 저장**을 누릅니다. 관측소 목록은 기록 당시 시점으로 조회하며 좌표가 있으면 직선거리를 표시합니다.
4. 관찰 시각이 있으면 해당 시각 직전 정시의 시간자료를 사용합니다. 예를 들어 12:34는 12:00 KST 자료입니다. 시각이 없으면 일자료를 사용하며, 당일 일자료는 조회하지 않습니다. 기온·습도·풍속·강수량을 표시하고 일자료는 평균·최고·최저 기온을 구분합니다. 누락값은 0으로 바꾸지 않습니다.
5. 저장값은 화면 재조회·재실행 시 자동 갱신하지 않습니다. 동일 관측소·종류·시점은 재사용합니다. **기상자료 다시 조회**는 확인 후 새 자료를 저장하고 해당 기록의 연결만 바꿉니다. 실패하면 기존 자료를 보존합니다.

### 비용과 전송 범위

- 사용자가 2026년 10월 24일 확인한 한도를 반영했습니다. Dynamic Map은 월 6,000,000회, Geocoding·Reverse Geocoding은 각각 월 3,000,000회, 기상청은 일 20,000회입니다. 네이버의 별도 로컬 일 제한과 기상청의 별도 로컬 월 제한은 두지 않습니다. 한국 날짜를 기준으로 SQLite에 호출 전 예약하며 실패도 차감합니다. 자동 재시도와 유료 대체 서비스는 없습니다.
- 화면에는 앱 집계와 한도를 표시합니다. 네이버 콘솔에서 확인한 사용량은 `.env`의 `NAVER_USAGE_SNAPSHOT_DATE`, `NAVER_MAP_USAGE_SNAPSHOT`, `NAVER_GEOCODE_USAGE_SNAPSHOT`, `NAVER_REVERSE_USAGE_SNAPSHOT`에 선택적으로 보관하며 확인 날짜와 함께 별도로 표시합니다. 참고값은 자동 갱신하거나 앱 집계에 더하지 않습니다. 제공자 실시간 사용량 조회 기능은 아닙니다.
- 화면의 **연동 상태·로컬 사용량**에서 이 DB의 시도 수를 확인합니다. 브라우저 SDK의 실제 제공자 집계와 다를 수 있으며 다른 앱·DB·장치 사용량은 합산하지 못합니다. DB 복원으로 카운터가 과거로 돌아갈 수도 있으므로 제공자 콘솔의 강제 제한이 최종 비용 차단 수단입니다. 로컬 코드만으로 청구액 0원을 보증하지 않습니다.
- 네이버에는 표시할 지도 영역, 검색 주소, 명시적으로 주소 확인을 요청한 좌표가 전달됩니다. 기상청에는 관측소 번호와 대상 시각만 전달합니다. 종명·메모·사진은 전송하지 않습니다. 관측소 거리는 로컬에서 계산합니다.
- 공개 Client ID는 지도 SDK에 필요합니다. Client Secret과 기상청 키는 백엔드에만 보관하며 외부 오류 본문·인증 URL은 사용자 응답에 포함하지 않습니다.
- 기록 입력은 지도·기상 연결 실패와 분리되어 있습니다. 지도 한도 도달 시 표와 직접 위치 입력을 사용하고, 기상은 저장된 자료를 계속 열람합니다.

### 연동 모듈과 API

- 프론트엔드: `MapView.tsx`, `naverMaps.ts`, `LocationPicker.tsx`, `WeatherPanel.tsx`; 기존 `App.tsx`, `SurveyForm.tsx`, `api.ts`, `models.ts`, `App.css`에서 연결합니다.

브라우저 사용 흐름도 별도 시험 DB에서 점검했습니다. 조사에 관찰 3마리·채집 1마리와 개별 날짜·장소를 가진 미발견 기록을 함께 저장하고 지도·표·검색으로 확인했습니다. 관찰 12:34에 저장된 12:00 ASOS 자료를 연결했으며 기상청 추가 호출은 없었습니다. 시험 DB에 일 한도 도달 상태를 만든 뒤 재조회 차단·기존 기상 보존·새 기록 저장을 확인했고, 시험 서버 재시작 후에도 기록과 기상이 유지됐습니다. 검증 후 개인 DB 연결로 복구했으며 시험 기록은 개인 DB로 복사하지 않았습니다.

### 기록 수정 사용 방법

조사를 선택하고 `기록 수정`을 누른 뒤 `수정 저장`을 누릅니다. 취소하면 기존 저장값을 유지합니다. 개별 날짜·위치가 비어 있는 기록만 조사 기본값을 따릅니다. 기존 기상자료는 보존하며 조건이 달라지면 이전 조건과 저장 자료를 표시합니다. 수정 저장과 저장 기상 읽기는 외부 API를 호출하지 않습니다. 다른 창의 수정과 충돌하면 입력을 유지하고 저장을 거부합니다. 변경 내용을 따로 보관한 뒤 취소·새로고침 후 다시 편집합니다.

수정 관련 검증: 별도 DB에서 기존 ID·생성 시각 보존, 추가 기록, 상속·개별 값 유지, 잘못된 입력의 전체 거부, 동시 편집 충돌, DB 오류, 재시작 후 재조회, 기상 연결 보존과 외부 재조회 없음이 통과했습니다. 브라우저에서 기존 입력값 표시, 수정 저장 후 표·상세 반영과 이전 기상 조건 안내를 확인했습니다.

Codex 브라우저에서 남은 수정 흐름 검증을 완료했습니다. 잘못된 채집 수량의 저장 거부 후 메모·수량 유지, 취소 확인 알림에서 계속 작성 시 입력 유지, 취소 확정 후 원래 메모·개체 수가 있는 상세 화면 복귀를 확인했습니다. 별도 시험 서버를 중지한 통신 실패에서도 오류 안내와 입력 유지가 확인됐습니다. 개인 DB는 변경하지 않았으며 지도·기상청 외부 호출 없이 검증했습니다. 서버의 오류·충돌 시 기존 데이터 보존과 재시작 후 재조회는 자동 테스트로 확인했습니다.


### 검색·종별 표·탐사 참고자료

- 관찰 기록 검색의 상세 필터는 날짜·장소·종·단계·성별·관찰/미발견·채집 여부·시각·좌표·기상 연결 상태를 지원합니다. 지도와 표는 같은 종별 검색 결과를 사용합니다.
- 기본 표는 국명·학명·장소·시간·저장 기상입니다. 표시 열 선택으로 부가 정보를 켜며 날짜·국명·수량 정렬과 조사 목록 전환을 지원합니다. 표 기상은 종별 기록에 연결한 저장 자료입니다.
- 표 화면 왼쪽의 통합 검색 양식에서 관찰 조건과 출현·탐사 조건을 함께 적용합니다. 별도의 관찰 기록 검색 / 탐사 대상 찾기 전환 버튼은 없습니다. 출현 기준일은 실제 관찰 날짜와 별개이며 성충 참고 자료로 계산합니다.
- 나비 기본 정보 탭의 기본 정보 편집에서 36구간 출현 기간, 분포, 미접 연도, 채집 확인과 출처를 입력합니다. 탐사 결과에서도 같은 편집창을 열 수 있습니다. 제공된 엑셀에서는 국명·학명·기주식물만 282종 반입했습니다. 기주식물은 219종에 있으며 63종은 미등록입니다. 소장·구매·출현·분포 자료는 반입하지 않았습니다.
- 새 API: GET /api/record-weather, GET /api/exploration?on=YYYY-MM-DD&region=지역, GET/PUT /api/species/{id}/reference. 검색·정렬·참고자료 저장은 외부 API를 호출하지 않습니다.
- DB 버전 4는 기존 observations에 source_type과 source_note를 추가합니다. 기존 기록은 직접 관찰과 빈 출처 근거로 유지됩니다. 복원은 서버를 종료하고 현재 DB를 보존한 상태에서 .before-v4-날짜.bak 복사본을 별도 DB 경로로 열어 확인하세요. 현재 코드는 이전 백업을 열면 버전 5로 이전합니다. 이전 코드로 돌아갈 때는 호환되는 이전 DB도 함께 선택해야 합니다.
- 검증: 백엔드 84개, 프론트엔드 검색 규칙 9개 테스트. 프론트엔드 테스트 실행은 frontend 폴더에서 `node --experimental-strip-types --test tests/recordSearch.test.mjs`입니다. 타입·린트·빌드와 Codex 브라우저에서 기본 열, 기상 필터, 선택 열, 미갱신 미접 제외, 남은 기간 정렬, 비율 갱신, 참고자료 오류·저장 후 재계산을 확인했습니다. 실제 지도 SDK 추가 호출과 수백 건 성능은 이번 검증에서 수행하지 않았습니다.

기주식물은 한살이 기간 열 오른쪽에서 확인하고 국명을 눌러 출처와 함께 수정합니다. 원문 문자열과 파일·시트·셀 출처를 보존하며 식물별 관계로 자동 분해하거나 생물학적 사실로 검증하지 않습니다. 이번 반입은 사용자 요청에 따라 별도 DB 백업 없이 한 트랜잭션으로 진행했고, 저장 후 282행을 원본과 대조했습니다. 데이터와 반입용 임시 파일은 Git에서 제외합니다.

나비 기본 정보와 종 선택 목록의 기본 순서는 호랑나비과 / 네발나비과 / 흰나비과 / 팔랑나비과 / 부전나비과입니다. 과 안에서는 엑셀의 아과 첫 등장 순서와 각 아과의 종 행 순서를 유지합니다. 검은눈그물나비는 뱀눈나비아과 끝, 푸른줄까마귀왕나비는 왕나비아과 끝으로 모았습니다. 정렬 버튼은 추가하지 않았으며 기본 정보 검색 결과도 원래 순서를 유지합니다. 표시 순서가 없는 신규 종은 기존 분류 목록 뒤에 등록 순으로 배치합니다. 이 순서는 사용자 지정 표시 규칙이며 모든 종 사이의 분기 순서를 확정한 계통 분석 결과가 아닙니다.


### 현재 화면 배치와 디자인 검증

왼쪽 패널에 제목·검색·필터·조사 목록을 모으고 맨 아래에 지도 / 표 / 나비 기본 정보 탭을 고정합니다. PC 왼쪽 너비는 240px로 고정하며 바깥 여백과 패널 간격은 모두 12px입니다. 오른쪽 본문 여백은 20px이며 흰색·#fbbc04 기반 테마를 사용합니다. 기존 설치 글꼴의 크기·굵기·대비를 조정했고 별도 폰트나 패키지는 설치하지 않았습니다.

검색 필터는 여섯 아이콘으로 묶었으며 이름 안내·적용 중 표시·전체 초기화와 기존 조건을 유지합니다. Codex 브라우저에서 종·채집·기상 조건 결합, 날짜 입력과 빈 결과, 초기화, 조사 등록·수정 저장 후 재조회, 지도·표·기본 정보 전환과 탐사 검색 접근을 확인했습니다. 1280×720, 1566×949, 390×844에서 배치와 가로 넘침을 확인했습니다. 지도는 시험 DB의 호출 한도로 외부 요청을 차단해 검사했으며 실제 지도 타일·위성지도·마커의 새 디자인 검증은 수행하지 않았습니다. 타입 검사·린트·Vite 빌드·검색 규칙 테스트 5건이 통과했습니다. 검증 후 원래 개인 DB 연결로 복구했습니다.


### 통합 관찰 기록표

표 화면의 왼쪽 양식에서 관찰 날짜·출처·종·단계·성별·결과·채집·위치·기상과 출현 기준일·목표 분포 지역·현재 출현·내 채집 이력·북한 서식·미갱신 미접·보호종 조건을 결합합니다. 지도에서는 같은 관찰 조건을 여섯 아이콘으로 제공하고 출현·탐사 조건을 펼칠 수 있습니다. 같은 조건의 여러 선택은 OR, 다른 조건들은 AND이며 기본적으로 탐사 제외 조건을 강제하지 않습니다.

표는 관찰 한 건당 한 행이며 기본 다섯 열을 유지합니다. 기본 정렬은 분류 순서이고 관찰 날짜·국명·수량·남은 출현 일수 정렬도 가능합니다. 출처·출현 기간·남은 일수·내 채집 이력·분포·근거는 선택 열입니다. 날짜·수량·일수가 없는 참고 값은 정렬 방향과 무관하게 뒤에 둡니다.

관찰 기록 없는 종 포함은 기본 켜짐입니다. 해당 종에는 종 참고 / 관찰 기록 없음과 분포 참고를 명시하고 실제 시각·기상·좌표를 만들지 않습니다. 모든 원본 관찰에서 한 번이라도 기록한 종은 필터에 걸러졌다고 참고 행으로 다시 생성하지 않습니다. 관찰 날짜·장소·출처·개체·기상 조건을 지정하면 관찰 기록 없는 종은 조건을 확인할 수 없어 제외됩니다. 종 참고 행은 지도 핀에 포함하지 않습니다. 기록 없는 종 참고 행은 기본 정보를 열지 않습니다. 종 정보 조회·편집은 나비 도감에서 수행하며 실제 관찰 행은 기존 상세·수정으로 연결합니다.

등록·수정창에서 직접 / 간접 관찰을 선택합니다. 간접 관찰에는 원문 주소나 자료명·관찰자 등 출처가 필수이며 채집 여부는 원 관찰자 기준입니다. 내 채집 이력 계산에는 직접 관찰의 채집 기록만 반영합니다. 크롤링·외부 사이트 자동 수집은 구현하지 않았습니다.

통합 화면은 시험 DB에서 출처 필수 검사, 입력 전환과 저장·수정·재조회, 출처와 탐사 조건 결합, 종 참고 편집, 지도·표의 조건 공유, 통신 실패 안내와 다시 읽기 복구를 확인했습니다. 실제 개인 DB는 이전 전후 8개 테이블의 기존 열 해시를 대조했고 282종과 참고자료·호출 집계가 유지됨을 확인했습니다. 지도는 시험 호출 한도로 차단했으므로 실제 SDK·타일·마커 추가 검증은 하지 않았습니다. 간접 출처 입력이나 오류 안내가 추가되는 등록창은 높이가 부족하면 내부 스크롤을 사용합니다.


## 나비 기본 정보와 한살이 기간

왼쪽 검색창에서 국명·학명을 검색하고 왼쪽 양식에서 등록합니다. 오른쪽 표는 국명 / 학명 / 한살이 기간 / 기주식물 / 서식지 / 습성 / 기타 순서입니다. 국명을 누르면 중앙 편집창이 열립니다. 한살이 구간마다 단계·시작/끝·도감 출처·판본·지역을 입력하고 저장하면 이전·현재 한살이 값이 이력에 남습니다. 기존 분포·채집·보호 정보 편집도 유지합니다.

그림은 알·유충·번데기·성충 네 행이며 옅은 막대는 참고 기간, 점은 실제 관찰, 상자는 가운데 50% 관찰 구간입니다. 단계 지정·사용자 확인 동정 관찰이 참고 구간 안에 5사례 이상 있어야 상자를 계산합니다. 마우스를 올리면 요약을 보고 클릭하면 출처와 사례를 확인합니다. 왼쪽 그림 조건에서 연도·지역·직접/간접 관찰을 선택합니다. 상세 계산 규칙은 [데이터 구조](docs/data-model.md)에 있습니다.

기존 282종의 한살이·서식지·습성은 임의로 채우지 않았습니다. 자료 미등록은 실제 부재를 뜻하지 않습니다. 별도 시험 DB의 가상 도감과 네 단계 28사례로 판본 수정·재조회·이력 보존 및 사례 창을 검증했습니다. 외부 지도·기상 API는 추가 호출하지 않았습니다.

## 환경 태그 사용

새 조사 또는 기록 수정에서 조사 공통 태그와 종별 추가 태그를 펼쳐 선택합니다. 기본 항목에 없는 이름은 찾기·추가 칸에 입력하고 태그 추가를 누릅니다. 같은 이름을 중복 생성하지 않으며 다음 입력부터 체크박스 목록에서 재사용합니다. 이름 추가는 즉시 기억하므로 기록을 취소해도 목록에는 남습니다. 선택 해제만으로 해당 환경이 없었다고 판정하지 않습니다.

태풍·관찰 전 강우·관찰 후 강우·하천 범람 등을 기본 제공하고 구체적인 날짜·정도는 메모에 적습니다. 흡밀·산란이나 그늘·아침 활동 같은 종의 습성은 도감의 습성 항목과 구분합니다. 검색은 왼쪽 출처·관찰 특성의 환경 태그에서 설정합니다. 여러 태그는 하나 이상 일치, 다른 필터와는 모두 일치해야 합니다. 공통 태그와 개별 태그를 함께 검색하며 표의 표시 열 선택에서 환경 태그 열을 켤 수 있습니다.

태그 저장·수정은 로컬 DB만 사용하며 외부 지도·기상 API를 호출하지 않습니다. 자동 갱신·이름 통합·태그 삭제는 하지 않습니다. 검증은 별도 시험 DB에서 수행했으며 자동 테스트는 백엔드 104건, 프론트엔드 17건입니다. 실제 지도 타일·마커는 이번에 추가 조회하지 않았습니다.
