# Butterfly Archive

개인의 나비 관찰·채집 기록과 소장 표본을 관리하는 Windows 로컬 프로그램입니다. React·TypeScript·Vite, FastAPI, SQLite를 사용합니다.

지도 / 기록 / 나비 도감 / 자료 수집을 제공합니다. 탐사·관찰·소장 관리, 휴지통 복구·완전 삭제, 검색·지도·저장 기상, 도감 세부 정보·한살이 밀도상자를 구현했습니다. 네이처링 확장과 iNaturalist 공식 API는 수집 대기함에서 검수 후 간접 관찰로 등록합니다. 논문 검색·PDF 추가·근거 입력 등록, 집 안 사진 메타데이터 전송과 별도 사본의 외부 읽기 전용 조회도 구현했습니다. 구글링 수집과 출현 예측은 미구현이며 사용자용 백업·복원은 보류입니다. 모바일 GPS와 공인 HTTPS의 남은 확인은 [미구현 및 확인 사항](docs/improvement.md)을 참조하세요.

## 평소 실행 방법

프로젝트 폴더의 **`나비 아카이브 실행.cmd`를 더블클릭**합니다. 서버가 꺼져 있으면 숨김 실행하고 준비가 끝나면 기본 브라우저를 엽니다. 이미 정상 실행 중이면 서버를 추가로 켜지 않고 화면만 엽니다. 자동 설치·API 조회·시스템 설정 변경은 하지 않습니다.

- 바탕 화면에 두려면 이 파일을 마우스 오른쪽으로 눌러 **보내기 → 바탕 화면에 바로 가기 만들기**를 선택하세요. 실행 파일 자체를 다른 폴더로 옮기지 마세요.
- 브라우저를 닫아도 서버는 유지되므로 네이처링 확장 전송을 계속 사용할 수 있습니다. Windows를 종료하면 서버도 종료됩니다.
- 시작 오류는 안내 창으로 표시하며 실행 로그는 Git 제외 경로 `.tmp/launcher-backend.log`, `.tmp/launcher-frontend.log`에 저장됩니다. 다른 프로그램이 같은 포트를 쓰면 임의로 종료하지 않습니다.
- 코드·설정을 변경한 뒤 서버 재시작이 필요하면 개발자에게 요청하거나 아래 수동 실행 방식을 사용합니다. 실행 버튼은 이미 켜진 서버를 강제로 재시작하지 않습니다.

수동 실행이 필요한 경우 프로젝트 폴더에서 PowerShell 두 개를 엽니다. 이미 설치되어 있으면 아래 실행 명령만 사용하며 패키지를 다시 설치할 필요가 없습니다.

첫 번째 PowerShell에서 백엔드를 실행합니다.

```powershell
.\backend\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

두 번째 PowerShell에서 화면 서버를 실행합니다.

```powershell
cd frontend
npm.cmd run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

브라우저 인증 세션은 `나비 아카이브 실행.cmd`로 여세요. 주소만 직접 열어서는 새 세션이 발급되지 않을 수 있습니다. 두 PowerShell은 사용하는 동안 켜 두고, 종료할 때 각각 Ctrl+C를 누릅니다. 프로그램을 종료해도 저장된 기록은 유지됩니다.

- API 상태: http://127.0.0.1:8000/api/health
- API 사용 명세: http://127.0.0.1:8000/docs
- 설정 파일이나 백엔드 코드를 바꾼 뒤에는 첫 번째 서버를 종료하고 다시 실행합니다.
- 개발 중 자동 재시작이 필요하면 백엔드 명령 끝에 --reload를 붙일 수 있습니다.
- 화면이 열리지 않으면 두 서버의 오류를 확인합니다. 포트가 사용 중이면 기존 프로그램 서버가 실행 중인지 확인하고 중복 실행하지 않습니다.
- 프론트엔드는 /api 요청을 Vite 개발 프록시로 백엔드에 전달합니다. 두 서버 모두 이 PC의 로컬 주소에만 바인딩합니다.

## 화면 사용

왼쪽 아래의 지도 / 기록 / 나비 도감 / 자료 수집으로 전환합니다. 왼쪽에는 검색·필터·등록·종별 기록 목록이 있고, 오른쪽에는 선택한 화면이 표시됩니다.

- 새 탐사: 왼쪽 + 버튼을 누르고 날짜·장소 또는 좌표와 종별 기록을 입력합니다. 관찰 시각과 모르는 개체 수는 비워 둘 수 있습니다. 여러 종은 입력창에서 전환하며 탐사 저장 시 함께 저장합니다.
- 수정: 표의 실제 관찰 행을 더블클릭하거나 국명 버튼에서 Enter를 눌러 중앙 상세창을 엽니다. 기록 수정을 누르면 같은 창에서 성장 단계·수량·성별·메모·위치 등을 수정합니다. 저장 후 상세로 돌아오며 편집 중 닫기·Esc·취소는 작성 내용 폐기 여부를 확인합니다. 입력 실패·편집 충돌 시 작성 내용은 유지됩니다. 저장 기상은 보존하고 날짜·위치 조건이 달라지면 이전 조건 자료로 표시합니다.
- 삭제: 상세의 탐사 전체 삭제 또는 이 관찰 삭제를 누르고 확인합니다. 기록은 휴지통으로 옮겨 지도·표·검색·관찰 집계에서 숨깁니다.
- 복구: 왼쪽 휴지통에서 복구합니다. 탐사 전체를 먼저 복구해야 그 안에서 따로 삭제한 관찰도 복구할 수 있습니다. 따로 삭제했던 관찰을 탐사 복구와 함께 자동 복구하지 않습니다.
- 삭제 시 사진 원본·메타데이터·태그·메모·저장 기상과 연결을 보존합니다. 휴지통 항목별 완전 삭제는 별도 확인 후 실행하며 사진 파일 정리는 제공하지 않습니다. 소장과 연결된 관찰은 소장 목록에서 관찰 연결을 해제하기 전에는 삭제하지 못합니다.
- 표: 왼쪽 검색 조건 위에서 관찰 기록 / 탐사 목록 / 소장 목록을 선택합니다. 탐사 목록은 종별 기록 0건인 탐사를 포함한 직접 관찰 탐사를 표시합니다. 날짜·장소 검색으로 찾고 행을 더블클릭하거나 날짜에 Enter를 눌러 상세를 열 수 있습니다. 관찰 기록의 기본 열은 국명·학명·장소·시간·기상이며 추가 열을 선택할 수 있습니다. 날짜·수량 등을 정렬합니다.
- 도감: 국명을 눌러 국명·학명·한살이 기간·기주식물·서식지·습성·세부 정보·동정 포인트와 출처를 편집합니다. 상태 태그와 분류 순서도 유지합니다.
- 소장: 같은 종·같은 취득 경로는 한 행으로 표시합니다. 수량에 마우스를 올리면 성별 수량을 봅니다. 암수 동시 선택 시 총수량 2 이상이 필수이며 모르는 성별 세부 수량은 비워 둡니다. 구매 자료는 개인 관찰을 생성하지 않습니다.
- 소장 항목 자체와 종 도감의 삭제는 이번 휴지통 범위에 포함하지 않습니다.

## 사진과 촬영 정보

1. 탐사 등록·수정 또는 소장 입력에서 사진·촬영 정보 관리를 엽니다.
2. JPEG·PNG를 선택하고 촬영 정보 검사를 누릅니다. 검사만으로 저장하지 않습니다. 파일은 이 PC의 백엔드에서 검사하며 외부 서버로 업로드하지 않습니다.
3. 사진의 날짜·시각·GPS는 후보입니다. 적용 버튼을 눌러야 탐사·관찰 입력에 반영됩니다. GPS 적용은 기존 장소명을 비우며 주소·기상을 자동 조회하지 않습니다. 소장 입력에는 촬영 시각·GPS를 자동 적용하지 않습니다.
4. 기본은 정보만 등록합니다. 증거 사진 보관을 체크한 항목만 원본 복사본과 썸네일을 data/photo에 저장합니다. 선택 항목 등록 후 탐사·소장 저장까지 해야 기록에 연결됩니다.
5. 기존 보관 자료를 다시 연결할 수 있습니다. 같은 파일은 해시로 재사용합니다. 기록에서 사진 연결을 해제해도 원본을 자동 삭제하지 않습니다.

현재 파일당 32 MiB, 60 MP 이내의 정지 JPEG·PNG를 검사합니다. HEIC·동영상은 지원하지 않습니다. 원본은 임의 변환하지 않으며 미리보기만 별도로 만듭니다. 촬영 정보가 없으면 파일 이름이나 수정 날짜로 관찰 시각을 추측하지 않습니다. 서로 다른 사진 1400장의 브라우저 전체 처리 성능은 미검증입니다.

## 지도·기상과 비용 제한

기존 키는 .env에서 관리합니다. 대표 계정의 무료 적용과 제공자 콘솔의 API별 강제 제한이 유지되어야 합니다. 예제 설정은 비활성이며 설정을 바꾸면 백엔드를 재시작합니다.

- 네이버 지도·주소 검색: MAPS_ENABLED, MAPS_FREE_TIER_CONFIRMED, NAVER_MAPS_CLIENT_ID, NAVER_MAPS_CLIENT_SECRET
- 기상청 API허브: KMA_ENABLED, KMA_API_PROVIDER=apihub, KMA_API_KEY
- 공개 Client ID는 지도 SDK에 필요하며 비밀 값이 아닙니다. Client Secret·기상청 키는 백엔드에만 보관합니다.
- 사용자 확인 기준 한도는 Dynamic Map 월 6,000,000회, Geocoding·Reverse Geocoding 각각 월 3,000,000회, 기상청 일 20,000회입니다. 호출 전 DB에서 한도를 예약하며 실패도 차감합니다. 자동 재시도·유료 대체 서비스는 없습니다.
- 연동 상태·로컬 사용량은 이 DB의 시도 수입니다. 제공자 실시간 청구액이나 다른 앱·장치의 사용량을 조회하지 않습니다. 콘솔의 강제 제한을 유지해야 하며 로컬 카운터만으로 청구액 0원을 보증하지 않습니다.
- NAVER_USAGE_SNAPSHOT_DATE와 NAVER_MAP_USAGE_SNAPSHOT, NAVER_GEOCODE_USAGE_SNAPSHOT, NAVER_REVERSE_USAGE_SNAPSHOT은 사용자가 확인한 콘솔 수치의 선택 참고값입니다. 자동 갱신하거나 앱 집계에 더하지 않습니다.

지도 일반 / 위성 전환은 기존 지도 객체의 유형을 바꿉니다. 위치 입력은 지도·주소로 위치 선택에서 결과를 고른 뒤 이 위치 적용을 누릅니다. 좌표 직접 입력도 가능하며 지도 실패가 기록 저장을 막지 않습니다.

기상은 기록 저장 후 상세에서 관측소 찾기 → 관측소 선택 → 기상 조회하여 저장 순서로 연결합니다. 시각이 있으면 직전 정시 시간자료, 없으면 완료된 과거 일자료를 사용합니다. 당일 일자료는 다음 날 이후 조회합니다. 누락값을 0으로 바꾸지 않습니다. 저장 자료는 로컬에서 재사용하고 자동 갱신하지 않습니다. 명시적 다시 조회 실패 시 이전 값을 보존합니다.

네이버에는 지도 영역·검색 주소·명시적으로 주소 확인을 요청한 좌표가 전달됩니다. 기상청에는 관측소 번호와 대상 시각만 보내며 거리 계산은 로컬에서 합니다. 종명·메모·사진은 외부 지도·기상 서비스로 보내지 않습니다. 기록 조회·수정·휴지통 삭제·복구는 외부 API를 호출하지 않습니다.

## 외부 자료 수집과 한살이 도표

- 자료 수집에서 네이처링을 선택합니다. Chrome 확장 설치·연결 키 입력 방법은 [확장 사용 안내](extensions/naturing/README.md)를 따릅니다. 개인 관찰이나 사진을 네이처링으로 전송하는 기능은 없습니다.
- 확장에서 현재 관찰을 개별 전송하거나 자동전송을 누릅니다. 자동전송은 현재 페이지의 다음 관찰부터 마지막까지 순차 진행하므로 시작 페이지도 필요하면 먼저 개별 전송합니다. 게시자가 위치를 비공개로 한 자료, 위치 미입력 안내·빈 위치·공개 좌표 쌍이 없는 자료는 제외합니다. 이전 확장 보관 자료의 전송에도 같은 기준을 적용합니다. 확장 팝업을 닫거나 다른 탭에서 작업할 수 있지만 수집 중인 탭·Chrome·로컬 서버는 켜 두어야 합니다. 재시작 후 자동 재개하지 않습니다.
- 앱에서 목록 새로고침 후 항목을 선택하고 관찰 기록에 추가합니다. 전체 선택은 현재 페이지에 적용됩니다. 체크는 사용자 검토 완료로 취급하며, 저장할 날짜·종·위치가 없는 항목은 확인 사유를 표시합니다. 등록된 자료는 대기 목록에서 빠지고 간접 관찰로 표시됩니다. 같은 출처 번호는 중복 등록하지 않습니다.
- 선택 자료 삭제는 수집 목록에서 숨기는 기능입니다. 삭제 취소 버튼은 사용자 요청으로 제거했습니다. 등록된 관찰의 삭제·복구는 표의 상세창과 휴지통에서 처리합니다. 원문은 보존합니다. 관찰 완전 삭제 시 등록 연결은 제거하고 수집 자료는 대기함에서 제외합니다.
- 가져온 기상은 네이처링 원문으로 표시하며 기상청을 자동 조회하지 않습니다. 지도 핀은 직접 관찰 주황색, 네이처링 파란색, iNaturalist 녹색입니다. iNaturalist는 아래 공식 API 수집 방법을 따릅니다.
- 도감 한살이 기간은 알·애벌레·번데기·어른벌레로 표시합니다. 초순 1~10일, 중순 11~20일, 말순 21~말일, 초중 6~15일, 중후 16~25일로 입력합니다. 원래 관찰 날짜는 바꾸지 않습니다.
- 수집 자료를 더블클릭하면 종과 성장 단계를 수정할 수 있습니다. 저장하면 해당 자료의 단계를 덮어쓰고 ‘사용자 지정’으로 표시합니다. 이후 기존 선택 등록 버튼으로 기록에 추가합니다. 직접 지정하지 않은 단계는 등록 당시 도감 기간으로 추정하며 겹치면 뒤 성장 단계를 택하고 맞는 기간이 없으면 미상입니다. 수동 지정 단계는 재수집해도 유지하며 도감 수정이 이미 등록된 관찰을 자동으로 재분류하지 않습니다.
- 도감 기간과 무관하게 단계별 실제 관찰 사례를 중복 제거한 뒤 20사례부터 밀도곡선과 사분위 구간을 결합한 상자 수염을 표시합니다. 가운데 가로 연결선은 밀도곡선으로 대체하고 중앙값·수염 끝·이상값을 유지합니다. 20사례 미만은 점, 1.5 IQR 통계적 이상값은 별도 점으로 남깁니다. 도감은 옅은 참고 막대로만 표시하며 겨울 관찰은 가장 긴 관찰 공백에서 연간 축을 나눠 잇습니다. 여러 발생 차수를 자동 확정하지 않습니다. 마우스 안내와 클릭 상세에서 표본 수·출처·추정 여부를 확인합니다. 이 그림은 수집된 관찰 날짜의 분포이며 출현 확률은 아닙니다.

## iNaturalist 공식 API 수집

자료 수집 → iNaturalist에서 사용합니다. Chrome 확장·로그인·API 키는 필요하지 않습니다. 네이처링과 같은 대기함·체크박스·등록·삭제·25건 단위 목록을 사용하며 출처별 목록은 분리합니다.

1. 처음에는 종별 과거 자료를 선택하고 국명 또는 학명으로 종 검색 → 검색 결과의 종 선택을 합니다. 대한민국이 기본이며 다른 국가·지역도 검색 결과에서 선택할 수 있습니다.
2. 관찰 날짜를 비우면 과거 전체를 대상으로 합니다. 자료 가져오기 · 이어서 수집을 누르면 게시물 번호 최신순으로 조회합니다. 한 번에 최대 2000건을 확인하며, 남은 자료는 같은 조건으로 다시 눌러 이어갑니다. 중지는 현재 요청 저장 후 적용됩니다.
3. 과거 수집 이후에는 나비 전체 최신 자료를 선택합니다. 같은 지역에서 과거 수집을 시작한 이력이 있으면 그 시작 이후에 게시된 자료를 모두 확인하여 과거 수집 중에 올라온 자료도 놓치지 않습니다. 과거 수집 이력이 없으면 첫 실행은 최신 게시물 200건으로 시작하며, 이후 같은 조건에서는 마지막 완료 기준 이후에 새로 게시된 모든 자료를 이어서 가져옵니다. 늦게 게시된 과거 관찰도 대상입니다. 관찰 날짜와 게시일을 혼동하지 않습니다. 기존 게시물의 수정 전체를 자동 추적하는 기능은 아닙니다.
4. 대기함에서 원문과 등록 가능 여부를 확인한 뒤 선택 자료 관찰 기록에 추가를 누릅니다. 등록 후 지도·표·조건에 맞는 한살이 통계에 반영하며 iNaturalist 핀은 녹색입니다.

Papilionoidea 분류 중 공개 좌표 오차가 50km 이하이거나 미상인 자료를 조회하며 흐림 위치도 포함합니다. 비공개·좌표 없음·50km 초과는 제외하며, 오차가 없는 자료는 정확도 미상으로 수집합니다. 흐림 위치는 대기함과 등록 기록에 공개 오차와 함께 표시하고 대략적 위치로 보존합니다. 이전 기준으로 완료된 과거 조건은 사용자가 다시 실행하면 중복 없이 재검사합니다. 도감 학명이 정확히 한 종과 일치해야 등록할 수 있으며 미연결 자료는 확인 사유와 함께 대기함에 남습니다. 제공된 현지 관찰 날짜를 유지하고, 시간대 오프셋과 날짜가 명확히 일치할 때만 시각을 반영합니다. 나머지 시각·단계·라이선스·관찰자 정보는 원문 스냅샷으로 보존합니다. 단계는 기존 도감 추정 규칙을 사용하고 기상은 임의로 생성하지 않습니다. 사진 파일은 다운로드하지 않습니다.

공식 API에 초당 약 1회, 앱에서는 한국 날짜 기준 하루 최대 5000회로 제한하고 실패도 차감합니다. 일시 오류는 한 번만 재시도하고 진행 위치를 보존합니다. 429·일일 한도 초과는 중단합니다. 페이지는 50건씩 처리합니다. 목록 새로고침은 저장된 대기함만 읽습니다. 외부에 전달하는 것은 사용자가 지정한 분류·지역·기간 조건이며 개인 관찰·좌표·사진은 전송하지 않습니다. 아주 큰 자료는 공식 내보내기 이용을 권장합니다.

진행 위치는 DB 옆의 `<DB 파일명>.inat-sync.json`에 조건별로 저장합니다. 화면·프로그램을 다시 열어도 같은 조건으로 이어갈 수 있으며 조건 변경은 별도 수집으로 처리합니다. 진행 파일 저장 실패 후 재실행해도 관찰 번호로 중복을 막습니다. 최초 수집 전 `.before-inaturalist-시각.bak` DB 보호 복사본을 생성합니다. DB와 진행 파일은 Git에서 제외하며 사용자용 백업·복원 기능은 아닙니다. DB를 수동 복원하면 해당 시점과 맞는 진행 파일도 함께 보존·검토해야 합니다.

## 논문 탐색과 사례 등록

자료 수집 → 논문 탐색에서 사용합니다. 접힌 상태에서도 보이는 테두리 없는 연한 노란 박스에 검색 조건을 두 줄로 묶었습니다. 추천·AI 요약·원문 자동 다운로드는 제공하지 않습니다.

- Crossref는 키·가입 없이 기본 사용합니다. KCI는 선택 연동이며 신청 없이 Crossref만 사용해도 됩니다. KCI를 사용할 때만 공식 OPEN API 키신청에서 발급받아 프로젝트 루트 .env에 `KCI_API_KEY=발급받은키`를 넣고 백엔드를 재시작한 뒤 화면을 새로고침합니다. 실제 키는 채팅·Git에 올리지 않습니다.
- 최신 나비 논문 / 국내 미기록종 관련 후보 / 사육·기주식물·생태를 선택하고, 종·추가 검색어·발표 기간을 지정하여 논문 갱신을 누릅니다. 기본 발표 기간은 비어 있으며 필요한 기간을 지정할 수 있습니다. 한 번에 수집처별 최대 50건을 확인하고 검색 페이지를 바꿔 더 가져옵니다. 목록 새로고침은 저장된 자료만 조회합니다.
- 언어는 한국어·영어·미상을 기본으로 표시합니다. 제목·초록 키워드로 관련 후보를 찾으므로 모든 관련 논문의 발견이나 국내 미기록종 여부를 보증하지 않습니다. Crossref에 등록되지 않은 국내 논문은 누락될 수 있고 제공자에 따라 초록·언어·정확한 발표일이 없을 수 있습니다. 월·연도만 알려진 발표일은 그대로 표시하며 날짜를 만들어 저장하지 않습니다.
- DOI로 제공자 간 중복을 묶고 DOI가 없는 KCI 자료는 원본 번호로 구분합니다. 원문 응답과 제공자별 원문을 보존하고 이미 저장한 빈 필드만 보완합니다. 사용자 개인 기록·메모·사진·좌표는 검색 API로 전송하지 않습니다. 초당 약 1회, 각 제공자별 한국 날짜 기준 하루 1000회로 제한하며 실패도 차감합니다. 무료 공개 API만 사용하고 유료 원문은 구매하지 않습니다.
- 논문 행의 간접 관찰 등록을 누르면 기존 등록창이 열립니다. 논문 출처가 자동으로 채워지고 근거 페이지·표·그림 번호, 원문에서 확인한 관찰 날짜·장소·종·단계 등을 입력합니다. 발표일은 관찰일로 자동 입력하지 않습니다. 필수 정보가 없으면 날짜나 위치를 추측해 등록하지 않습니다.
- 한 논문에서 여러 사례를 등록할 수 있고 같은 입력·근거의 중복 제출은 거부합니다. 저장 후 표·지도·조건에 맞는 한살이 통계에 간접 관찰로 반영합니다. 도감 기간으로 자동 단계를 추정하지 않으며 사용자가 원문을 확인해 입력합니다. 소장이나 개인 직접 채집 이력으로 자동 편입하지 않습니다.
- 휴지통 이동·복구 시 논문 연결과 근거를 보존합니다. 완전 삭제 시 관찰 연결만 제거하고 논문은 보존합니다. KCI 키가 없거나 만료되면 Crossref는 계속 사용할 수 있으며 기존 저장 논문과 관찰은 유지됩니다.

## 데이터와 설정

기본 DB는 data/butterfly.sqlite3, 선택 보관 사진은 data/photo입니다. .env의 BUTTERFLY_DB_PATH는 프로젝트 루트 기준이며, 시험 사진 폴더는 BUTTERFLY_PHOTO_DIR로 분리할 수 있습니다.

현재 DB 구조는 버전 14입니다. 이전 버전의 기존 DB는 시작 시 보호 복사본 .before-v14-시각.bak를 만든 뒤 필요한 변경만 트랜잭션으로 적용합니다. 실패 시 DB 변경을 되돌리고 기존 파일을 초기화하지 않습니다. 버전 10은 수집 원문·변경 이력·확장 연결 키 해시, 버전 11은 수집 자료와 등록 관찰의 연결·원문 및 단계 추정 스냅샷을 추가합니다. 버전 12는 논문과 논문·관찰 연결, 버전 13은 PDF 파일, 버전 14는 모바일 사진 대기함·연결 정보를 추가합니다. 같은 버전에서는 이전을 반복하지 않습니다. 스키마 보호 복사본은 사용자용 백업·복원 기능과 별개입니다.

.env·키·토큰·개인 기록·원본 사진·로컬 DB·보호 복사본·반입 내역은 Git에서 제외합니다. 소스 코드에 직접 적은 개인정보까지 .gitignore가 자동 판별하지는 않습니다. 휴대폰 사진과 앱에 입력한 메모·위치·소장 기록은 서로 다른 자료입니다.

## 처음 설치하거나 다른 PC에 구성할 때

기존 PC에서 평소 실행할 때는 이 과정을 반복하지 않습니다. Node.js 24, Python 3.13을 사용하며 정확한 의존성은 잠금 파일과 설치 목록을 따릅니다. 패키지 변경은 별도 승인을 받고 진행합니다.

```powershell
py -3.13 -m venv backend/.venv
.\backend\.venv\Scripts\python.exe -m pip install -r backend/requirements-dev.txt
cd frontend
npm.cmd ci
cd ..
```

가상환경 활성화나 Windows 실행 정책 변경은 필요하지 않습니다. 사진 검사는 프로젝트 가상환경의 Pillow 13.0.0을 사용합니다. 실행만 구성할 때는 requirements-dev.txt 대신 requirements.txt를 사용할 수 있습니다.

## 검증 명령

프로젝트 루트에서 실행합니다. 테스트는 별도 임시 DB를 사용하며 실제 외부 API 호출을 차단합니다.

```powershell
.\backend\.venv\Scripts\python.exe -m pytest backend/tests -q -c backend/pytest.ini
.\backend\.venv\Scripts\python.exe -m pip check
node --experimental-strip-types --test frontend/tests/*.test.mjs
cd frontend
npm.cmd run lint
npm.cmd run build
cd ..
```

Starlette TestClient의 httpx 사용 중단 예정 경고가 남아 있습니다. 삭제·복구의 연결 보존·충돌·실패와 DB 이전 롤백은 자동 테스트로 검증합니다. 수백 건·대량 사진의 전체 브라우저 성능과 실제 API 추가 검증은 수행 범위를 별도로 구분합니다.

프론트엔드는 frontend/src, 백엔드는 backend/app, API 테스트는 backend/tests에 있습니다. 프론트엔드 의존성은 package.json·package-lock.json, 백엔드는 requirements.in·requirements-dev.in과 고정된 requirements.txt·requirements-dev.txt로 관리합니다.

비공개 GitHub 저장소는 https://github.com/MirNaru/butterfly-archive이며 기본 브랜치는 main입니다. 사용자 요청 없이 Commit·Push하지 않습니다.

논문 탐색의 노란 검색 박스 안에서 KCI 안내 위의 **PDF 직접 추가**로 로컬 PDF를 여러 편 선택할 수 있습니다. PDF는 로컬에 원본 그대로 복사하며 외부에 보내지 않습니다. PDF 원문과 쪽별 추출 텍스트는 수집 논문 행에서 확인합니다. 일반 파일 추가는 관찰을 자동 생성하지 않으며, 원문을 확인한 뒤 해당 논문의 **간접 관찰 등록**을 사용합니다. 텍스트 없는 스캔 PDF는 OCR이 필요하고, 다단 편집·표의 추출 순서는 원문과 다를 수 있습니다.


## 집 안 사진 전송과 외부 읽기 전용 조회

입력과 조회는 서로 다른 서버·인증으로 분리합니다. 외부 도메인에는 사진 전송이나 원본 기록 API를 연결하지 않습니다.

### 집 안에서 사진 정보 보내기

1. `나비 모바일 연결.cmd`를 실행합니다. 현재 내부 주소는 `https://192.168.75.181:8443`입니다. 내부 IP 예약을 권장합니다. 인터넷 포트포워딩을 사용하지 않습니다.
2. `data/집안사진전송인증서.crt` 공개 인증서만 USB 등으로 휴대폰에 옮겨 CA 인증서로 설치합니다. 같은 폴더의 `.key` 파일은 옮기지 않습니다. Android 버전에 따라 설정의 보안 및 개인정보 보호 → 기타 보안 설정 → 기기 저장공간에서 설치 → CA 인증서에 있습니다. 인증서 경고를 그냥 넘기지 말고 설치 후 경고 없이 열리는지 확인합니다.
3. PC 자료 수집 → 내 사진 → 집 안 휴대폰 연결·관리에서 10분짜리 일회용 연결 코드를 발급하고 휴대폰에 입력합니다.
4. 갤러리 또는 원본 파일 선택에서 JPEG·PNG를 골라 촬영 시각·GPS를 확인하고 메타데이터만 전송합니다. 갤러리 선택에서 GPS가 없으면 원본 파일 선택으로 내 파일 → DCIM → Camera의 같은 사진과 비교합니다. Android·브라우저에 따라 이 경로에서도 위치 정보가 가려질 수 있으므로 복원을 보장하지 않습니다. 같은 파일은 선택 경로만 함께 표시하고 중복 전송하지 않습니다. 원본·미리보기·HEIC·동영상 전송은 현재 지원하지 않습니다.
5. PC 대기함에서 같은 관찰의 사진을 묶고 종·성장 단계·날짜·위치를 검수해 직접 관찰로 등록합니다.

서버는 지정한 내부 IP에서만 수신하고 Windows 방화벽과 서버 양쪽에서 집 안 주소 범위를 확인합니다. `setup_lan.ps1`은 현재 PC 192.168.75.0/24와 Wi-Fi 공유기 쪽 192.168.45.0/24를 허용하도록 구성했습니다. 다른 네트워크로 옮기면 자동으로 모든 사설망을 허용하지 않고 설정을 다시 확인합니다. 이중 공유기 환경에서 휴대폰→PC 연결 도달은 확인했으며, 실제 휴대폰의 사진 선택에서 GPS가 읽히지 않는 문제가 남아 있습니다. PC로 전달된 JPEG 한 장에서는 GPS와 같은 추출 코드의 정상 동작을 확인했으나 휴대폰 선택 경로의 원인은 확정하지 않았습니다. Bluetooth는 보류합니다.

PC가 켜져 있어야 하며 사진 읽기·전송 중에는 화면을 켜둡니다. 한 번에 최대 500장·파일당 32MB이고 순차 처리합니다. 실패 항목 재시도 시 SHA-256으로 중복을 확인합니다. 브라우저 종료 후 미전송 목록은 유지하지 않습니다. 파일에 없는 날짜·GPS를 파일명·수정 시각·현재 위치로 채우지 않습니다. 추출 원문과 검수값을 구분합니다.

### 외부에서 내 자료 읽기

- 주소: `https://archive.mirnaru.kro.kr`. 사용자 요청으로 공인 인증서 자동 재시도를 시작했습니다. 인증서 발급·외부 접속 완료를 뜻하지 않으며 현재 상태는 실행 로그와 실제 외부 접속으로 확인해야 합니다.
- PC 자료 수집 → 내 사진 → 외부 읽기 전용 조회·사본 관리에서 조회용 사본 갱신과 별도의 조회 코드 발급을 사용합니다.
- 등록된 관찰·도감·소장 자료를 조회하며 검색·과·성장 단계·직접/간접·날짜 필터를 사용할 수 있습니다. 30건씩 표시합니다. 지도와 PC의 상자수염그림 화면을 그대로 옮긴 것은 아닙니다.
- 사본은 등록된 좌표·장소·메모를 포함합니다. 사진 파일·수집 대기 자료·API 키·원본 SQLite 파일은 제공하지 않습니다. 화면에 전달한 조회 자료는 로그인한 기기에서 보관할 수 있으므로 원본 DB 접근 차단과 자료 복사 방지는 다릅니다.
- 원본 변경은 자동 공개하지 않습니다. 사용자가 PC에서 사본을 갱신해야 외부 조회에 반영됩니다. 조회 기기 연결은 PC에서 전체 해제할 수 있습니다.

`setup_viewer.ps1`은 별도 로컬 계정 `ButterflyArchiveView`와 `C:\ProgramData\ButterflyArchiveViewer` 실행 환경을 준비합니다. 현재 구성은 외부 사이트 가입을 요구하지 않습니다. 원본 프로젝트·DB 읽기와 사본·실행 코드 쓰기를 해당 계정에 금지합니다. 사본은 읽기 전용, 조회 인증 저장소·로그·TLS 저장소만 쓰기를 허용합니다. 실행 자격은 현재 Windows 사용자만 해독 가능한 DPAPI 형식으로 프로젝트의 Git 제외 data 폴더에 보관합니다. 서버는 관리자 권한으로 실행하지 않으며 Windows 시작 시 자동 실행하지 않습니다.

조회 계정은 서버 실행용으로 활성화하되 `Winlogon\SpecialAccounts\UserList`의 해당 계정 DWORD 값 0으로 로그인 화면의 사용자 목록에서 숨깁니다. 다른 사용자의 표시나 자동 로그인 설정은 변경하지 않습니다. 숨김 설정 전 값은 Git 제외 `data/viewer-login-visibility-before.json`에 보관합니다. 사용자 목록 숨김은 파일 접근 제한을 대신하지 않습니다.

`나비 외부 조회 실행.cmd`는 제한 계정으로 조회 서버와 공인 HTTPS를 시작합니다. 외부 도메인의 인증서와 80·443 포트 전달이 준비되어야 인터넷 접속이 가능합니다. 2026-11-04 공인 인증서 신뢰 검증과 사용자 도메인 접속을 확인했습니다. 현재 실행·포트·인증서 상태는 다시 확인해야 합니다. ZeroSSL 전환은 취소했습니다.

PC 실행기는 같은 PC의 다른 계정이 내부 API를 우회 호출하지 못하도록 자동 로그인 세션을 엽니다. 세션 만료 시 기존 `나비 아카이브 실행.cmd`로 화면을 다시 열면 됩니다. 네이처링 확장의 기존 Bearer 연결 키 수신은 유지합니다. Vite 개발 서버는 외부 공개하지 않습니다.

계정·권한·실행 파일의 변경 전후 설정은 data와 .tmp에 보관합니다. 보안 구성을 제거하거나 이전 코드로 돌아갈 때는 외부 서버를 먼저 중지하고 ACL·계정·PC 인증을 함께 검토해야 합니다. 단순 코드 되돌리기만으로 보안 설정이 자동 복구되지는 않습니다.


내 사진 대기함에서는 같은 탐사의 사진 정보를 선택해 날짜·장소·좌표를 확인하고 탐사를 먼저 등록합니다. 등록 후 **관찰 추가하기**에서 기존 기록 수정 창을 열어 **종별 기록 추가**로 여러 종을 입력합니다. 사진 정보는 탐사에 연결하며 관찰 시각을 자동으로 채우지 않습니다. PC 원본 추가는 기존 사진 관리 기능을 사용합니다.

### Android 집 안 사진 전송 앱

Android 16·One UI 8.5에서 원본 촬영 정보 추출을 확인하고 기존 집 안 대기함으로 메타데이터를 보내는 앱을 추가했습니다. 사진 다중 선택·미리보기·연결 코드·암호화된 세션·전송 및 실패 재시도를 지원합니다. 개발 환경과 현재 검증 범위는 [Android 안내](android/README.md)를 따릅니다. 원본 사진은 전송하지 않으며 실제 사진 한 장을 S23 Ultra에서 전송하고 PC 대기함 표시와 DB 재조회를 확인했습니다.

관찰·수집 자료의 종 입력에서는 국명이나 학명을 입력하고 검색 결과의 종을 선택합니다. 현재 종은 도감 순서 그대로 목록 내부 스크롤로 보여 줍니다. 새 직접 관찰은 탐사 날짜를 사용하며 다른 날은 별도 탐사로 등록합니다. 기존 개별 날짜와 외부 수집 원문은 유지합니다.
